1.3 初始化与赋值：出生与改写是两回事

上一课你见过 int x; 的注释——"里面的值是垃圾"。这可不是吓唬人。这一课讲清楚"给对象第一次值"和"给已有对象换值"的区别，并介绍 C++ 里最值得养成的书写习惯。

📐 概念

初始化（initialization）：对象创建时给它初始值。一生只发生一次。

赋值（assignment）：对象创建之后，用 = 覆盖当前值。可发生任意次。

初始化的三种写法

int a = 5;    // 拷贝初始化（copy initialization）
int b(5);     // 直接初始化（direct initialization）
int c{ 5 };   // 列表初始化（list initialization）★ 推荐这是一种

三者对 int 效果相同。但看这个实验：

int x = 3.5;    // ✅ 编译通过！x 得到 3（小数被悄悄扔掉）
int y{ 3.5 };   // ❌ 编译错误！

= 3.5 做了一次隐式转换：double 被截断成 int，编译器不吭声。{ 3.5 } 则被拒绝——列表初始化禁止"窄化转换"（narrowing conversion），即"装不下就报错"。

⚠️ 为什么截断是隐患

3.5 截成 3 看似无害，但真实代码里往往是：int itemCount{ cartValue };——购物车金额 199.99 被悄悄截成 199，钱不见了，没有任何报错。这类 bug 可能潜伏几个月。列表初始化把"运行时的数据事故"提前变成"编译期的报错"，用编译时间换运行时安全，非常划算。

选择以下哪一行无法通过编译？

未初始化：看不见的地雷

int main()
{
    int x;                 // 定义了，但没给值
    std::cout << x;        // ❓ 读到的是什么？
}

答案：未定义行为（Undefined Behavior，UB）。局部变量不会自动清零，x 的内存里残留着之前某个程序用过的字节。读它、用它，结果没有任何保证：可能打印随机数，可能打印 0，可能崩溃，甚至可能表现"正常"。

⚠️ UB 的可怕之处在于"不可预测"

未定义行为的标准后果是"什么都可能发生"：今天碰巧正常，明天换了编译器就崩；Debug 好好的，Release 就炸（0.2 节你刚见过这个病例）。不要试图"利用"UB 的某种表现，唯一的正确姿势是消灭它。

✅ 最佳实践：变量定义时总是初始化
int x{};          // 列表初始化无值 → 零初始化，x = 0，安全
int count{ 0 };   // 或给一个明确的初值
int total{ 10 };  // 有意义就写有意义的

记住口诀：定义即初始化，永远别让变量"裸奔"。成本为零，收益是消灭一整类 UB。

判断"int x{}; 里的 x 值是未定义的，和 int x; 一样危险。"

🎯 预测输出（三段，用空格分隔）：

int value{ 10 };
std::cout << value << ' ';   // ①
value = 5;
std::cout << value << ' ';   // ②
int truncated = 3.9;
std::cout << truncated;      // ③
