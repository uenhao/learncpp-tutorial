1.4 iostream：程序与用户的对话

到目前为止程序只会"自说自话"。这一课让程序能听（cin）也能说（cout）——并顺便理解一个日后天天打交道的概念：流（stream）。

📐 概念：流与运算符方向

流（stream）：数据缓缓流过的通道。想象一条传送带。

std::cout：输出流，通向屏幕。<< 叫插入运算符，方向指向 cout——"把数据塞进输出流"。

std::cin：输入流，来自键盘。>> 叫提取运算符，方向指向变量——"从输入流取出数据放进变量"。

#include <iostream>

int main()
{
    std::cout << "Enter your age: ";   // 提示（不换行，光标停在同一位）

    int age{};                          // 先准备好变量（零初始化！）
    std::cin >> age;                    // 从键盘读一个整数放进 age

    std::cout << "Next year you will be " << age + 1 << '\n';
    return 0;
}

三个值得注意的细节：

  1. 先定义变量再读入：int age{} 的零初始化在输入失败时兜底（age 至少是 0，不是垃圾）。
  2. 链式输出从左到右：<< age + 1 先算出 26 再送进流。
  3. cin 默认跳过空白：空格、Tab、换行都当分隔符。

📐 为什么有"缓冲区"这回事

往屏幕写一个字符的开销远大于往内存写。所以 cout 把输出先攒在缓冲区（buffer）里，攒多了或程序结束时才真正写到屏幕。刷新（flush）= 强制"立刻倾倒缓冲区"。大多数时候你不需要手动刷新——缓冲区会在恰当时机自动倾倒。

选择交互式程序里，什么时候必须用 std::endl 而不是 '\n'？

当用户不按套路输入

cin >> age 假设用户会输入一个整数。如果用户输入了 abc 呢？

⚠️ 反例：提取失败

用户输入 abc 回车后：① age 保持它的初始化值 0；② cin 进入"失败状态"，之后所有提取全部被跳过，直到你显式恢复它。③ 程序不会崩溃，只是"看起来跳过了输入"。

本章不需要你处理这种情况——但你要知道它存在。学完条件语句后你会用 if (std::cin >> age) 这种写法优雅地防御它。

💭 思维转变：输入是"请求"不是"命令"

初学者以为 cin >> x 一定能拿到值；成熟的写法把每一次输入都当作可能失败的请求。"我不假设用户是善意的"——这个心态从命令行程序一直适用到 Web 安全。第 1.11 课设计第一个真实程序时，你会第一次把这个心态用起来。
