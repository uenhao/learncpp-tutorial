1.5 关键字、命名与代码格式

写程序不只是写给编译器看，更是写给三个月后的自己和同事看。这一课讲两件事：什么样的名字合法，什么样的名字好。

标识符的硬规则（编译器强制）

📐 概念：标识符（identifier）

变量、函数等的名字。规则：

  • 只能用字母、数字、下划线
  • 不能以数字开头
  • 不能是关键字（int、return、class……编译器保留字）
  • （加分规则）不要用双下划线或下划线开头——那些留给编译器实现者

好名字的软规则（人类约定）

风格示例用途
camelCase 驼峰totalPrice变量、函数（本教程采用）
PascalCase 帕斯卡PlayerInventory类型、类（后续章节）
snake_case 蛇形total_price也可，统一即可

风格本身不重要，一致才重要。但"有意义的名字"更重要——对比：

int res = calc(p, q);              // res？p？q？读代码的人只能猜
int totalPrice = calcTotal(unitPrice, quantity);   // 自解释
✅ 命名的两条检验标准
  1. 不读实现也能猜对用途：看到 daysUntilDeadline 就知道它是什么；看到 dup 就未必了。
  2. 在它的作用域里不产生歧义：循环里的 i、j 可以接受（传统、且生命周期极短）；但函数级的 data、temp、result2 都是坏味道。

选择以下哪个名字合法但不该用？

空白与格式：编译器不在乎，人在乎

下面两段代码对编译器完全等价：

int width=3;int height=4;std::cout<<width*height;
int width{ 3 };
int height{ 4 };
std::cout << width * height;

但可读性天差地别。几条最低限度的排版约定：

  • 每条语句一行，块内语句用 4 空格缩进
  • 花括号风格二选一并坚持：换行或同行都行
  • 运算符两侧加空格：x * y + 1
  • 别手工较劲——用 clang-format 一键统一（clang-format -i *.cpp）
⚠️ 空白的例外：字符串不能折行
std::cout << "Hello
world";    // ❌ 编译错误：字符串字面量必须写在一行
std::cout << "Hello "
              "world";  // ✅ 相邻字符串字面量自动拼接（或拆成两个 <<）

判断"代码格式只是美观问题，不影响程序行为。"

💭 思维转变：代码的读者首先是人

编译器不在乎名字叫 x 还是 totalPrice，但调试时的人在乎。命名和格式是你每天在写"文档"——代码即文档。learncpp 反复强调：当你的代码需要一条注释才能看懂时，先考虑改名字。
