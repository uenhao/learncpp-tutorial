10.1 类型转换与推导

第 4 章埋的"类型转换地图"在这里补全成册。先回顾地基（4.12 课）：隐式转换（编译器自动做）、static_cast（显式声明）、窄化危险。

数值提升（promotion）：安全的小→大

📐 概念：数值提升（numeric promotions）

窄类型 → 宽类型的无损转换，编译器自动做：

  • 浮点提升：float → double（值不变）
  • 整型提升：unsigned char/short → int（值不变——int 至少能装下它们）

安全的原因：目标类型的范围完全覆盖源类型，无信息损失。

数值转换（conversion）：有损的语义变化

📐 概念：数值转换（numeric conversions）

非提升的类型转换——可能丢失数据：宽→窄（int→short）、浮点↔整数（3.9→3）、有符号↔无符号。五大类：

  1. 整型 ↔ 整型（范围可能丢失）
  2. 浮点 ↔ 浮点（精度可能丢失）
  3. 浮点 → 整型（小数部分丢弃）
  4. 整型 → 浮点（大整数可能损失精度）
  5. 指针/bool 相关（后续章节）
int n{ 300 };
short s{ n };       // 300 放不进 short(最大 32767？不——short 够)。
                    // 换个大数试试：
int big{ 40000 };
short s2{ static_cast<short>(big) }; // 需显式：窄化被 {} 拒绝

double d{ 0.1 };    // 二进制近似存储（4.3 课）

算术转换（arithmetic conversions）：二元运算的类型协商

📐 概念：usual arithmetic conversions

+ - * / %、比较、位运算等二元运算符要求两个操作数同类型。类型不同时，编译器按"等级表"协商出公共类型（common type）：

long double > double > float > long long > long > int

规则简化：① 整型遇浮点 → 整型方转成浮点方；② 都是整型 → 低等级转成高等级。

int x{ 2 };
double y{ 3.5 };
std::cout << x + y << '\n'; // x 提升为 double：5.5（浮点除法同理）

short a{ 2 };
short b{ 3 };
std::cout << a + b << '\n'; // short 提升为 int 再算——结果也是 int！
⚠️ 意外收获：short + short 得 int

整型提升让 short/unsigned char 参与运算时先变 int——所以 short + short 的结果类型是 int。想存回 short 需要显式转换（或赋值时的隐式窄化）。这也是 4.5 课"别为省内存用 short"的又一理由。

auto：让编译器替你写类型（10.8）

📐 概念：auto 类型推导

auto：从初始化式推导变量类型。规则：推导自初始化表达式的类型（字面量后缀、函数返回值都参与）。

auto d{ 5.0 };   // 5.0 是 double → d 是 double
auto i{ 1 + 2 }; // int → i 是 int
auto s{ add(5, 6) }; // add 返回 int → s 是 int
auto f{ 1.23f }; // f 后缀 → float
const auto b{ 5 };  // const auto 组合合法
⚠️ auto 的两条纪律
  • 必须有可推导的初始化式：auto x;（无初始化）编译错误；
  • 别滥用：初始化式含义明确时才用（函数返回值、长类型名）。auto x{ 5 } 比 int x{ 5 } 省不了事还牺牲了自解释性——原文建议类型不明显时才用 auto。

类型别名（10.7）：using 起别名

using Distance = double; // Distance 是 double 的别名

Distance miles{ 3.4 };   // 实际就是 double
// 编译期替换，无运行时开销；typedef 是老写法，现代 C++ 用 using

别名不产生新类型——Distance 与 double 完全可互换。价值在语义：Distance 说明了这个 double 是什么。

预测输出什么？

short a{ 2 };
short b{ 3 };
std::cout << a + b << ' ' << sizeof(a + b);

判断"auto 定义的变量没有类型，是'动态类型'。"

💭 思维转变：转换地图成册，auto 是"便利贴"

现在你拥有完整的转换地图：提升（安全）→ 转换（可能丢）→ 窄化（{} 拦截 / static_cast 声明故意）→ 算术协商（公共类型）。auto 则是类型系统的便利贴——类型由初始化式决定这条铁律不变，只是书写方式变了。用 auto 的判断标准回归 1.5 课的老原则：读者能不能一眼看懂？能，auto 是福利；不能，老老实实写类型。
