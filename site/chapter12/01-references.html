12.1 引用：给对象起第二个名字

第 12 章是 C++ 的分水岭。它回答的问题你早已遇过：2.2 课"形参是拷贝，改它不影响实参"——那时说"想影响得学引用"；5.4 课"string 拷贝很贵"——那时说"只读场景用 view"。引用（reference）就是这一切的机制核心。

📐 概念：值类别（value category）——lvalue 与 rvalue

表达式除了类型（4.1 课），还有一个属性：值类别。

  • lvalue（左值）：有身份、有持久地址的对象——变量是典型 lvalue。可以出现在赋值号左边。
  • rvalue（右值）：临时的值——字面量、x + y 的结果、函数返回的临时对象。只能出现在右边。

类比：lvalue 是"房子"（有地址），rvalue 是"包裹"（在流转中）。引用绑房子，绑不了包裹（const 引用例外，后面讲）。

📐 概念：左值引用（lvalue reference，&）

引用 = 已有对象的别名（alias）。声明时加 &：

int x { 5 };
int& ref { x };   // ref 绑定到 x —— ref 就是 x 的另一个名字

ref = 7;          // 通过引用改 x！
std::cout << x << '\n'; // 7
std::cout << &x << ' ' << &ref; // 地址相同——同一个对象！
⚠️ 引用的三条铁律
  1. 必须初始化（绑定到某个 lvalue）——没有"空引用"；
  2. 非 const 引用只能绑定到可修改的 lvalue——int& r{ 5 };（rvalue）和 int& r{ c };（const 对象）都非法，否则通过引用改它们就违反了常量性；
  3. 绑定后不可重绑——对引用赋值改的是被引用对象，引用本身永远指向初次绑定的那个对象。

引用的三大用途之一：按引用传递（pass by reference）

📐 概念：pass by reference

把形参声明为引用类型，函数收到的就是实参本尊（别名），无拷贝、可修改：

void addOne(int& y)   // y 是实参的别名
{
    ++y;              // 直接修改调用者的变量！
}

int main()
{
    int a{ 5 };
    addOne(a);        // a 变成 6
    std::cout << a << '\n';
}

5.4 课 string_view 解决"只读不拷贝"；引用解决"要改不拷贝"。两者合起来：

意图参数类型2.2 课预言的兑现
只读不拷贝const std::string& 或 std::string_view"引用传递"登场
修改实参std::string&（非 const 引用）"函数无法影响调用者变量"被打破
只读且小按值即可int 等基本类型拷贝极便宜
✅ 原文最佳实践：优先 const 引用

除非函数需要修改实参，否则优先按 const 引用传递（pass by const lvalue reference）。const 引用还有一项特权：能绑定 rvalue——printRefConst(5)（字面量）、printRefConst(c)（const 对象）都合法（绑定到临时对象）。而非 const 引用绑不了这些。这让 const 引用参数来者不拒。

预测输出什么？

void change(int& ref)
{
    ref = 99;
}

int main()
{
    int a{ 5 };
    change(a);
    std::cout << a;
}

判断"int& r{ 5 }; 合法——把引用绑定到字面量而已。"

💭 思维转变：引用是"别名"不是"副本"

1.2 课的模型"名字是标签，对象是盒子"在这里升级：一个盒子可以贴多张标签。ref 和 x 是同一盒子的两张标签——通过任何一张操作的都是同一个盒子。这也把 5.4 课 string_view 的"视图"思想接上了：view 是只读的眼镜，非 const 引用是可读写的遥控器。记住"别名不拥有对象"（对象销毁，别名悬空——7.4 课 string_view 悬空的教训同样适用），下一课的指针会更彻底地暴露这一点。
