13.1 枚举与结构体：自定义类型的开始

基本类型装不下"业务"——颜色、状态、一个员工。本章开始造自己的类型：枚举管"有限的取值集合"，结构体管"相关数据的打包"。1.7 课"数据要成组"的痛点在此兑付。

枚举（enum）：受限的取值集合

📐 概念：枚举（enumeration）

定义一个类型，它的值只能是指定的几个常量（枚举器）：

enum Color
{
    red,     // 枚举器：逗号分隔
    green,
    blue,
};           // 注意分号

Color apple{ red };   // ✅
Color hat{ 2 };       // ❌ 编译错误：2 不是 Color 的枚举器

价值：类型即文档——Color 类型的变量只可能装三种值，读代码的人一眼看懂取值空间。

⚠️ 非限定枚举（unscoped enum）的两大问题
  1. 枚举器泄漏到外层作用域：Color 的 red 和 Fruit 的 red 不能共存（重名冲突）——2.9 课命名空间要手动包一层；
  2. 可以和整数隐式比较：color == fruit（不同枚举类型）居然编译通过还可能为真——底层都是整数在比较，类型安全形同虚设。

解法：限定枚举（enum class / scoped enum）

📐 概念：enum class（C++11）
enum class Color
{
    red,
    green,
    blue,
};

Color color{ Color::red };  // 枚举器必须加 Color:: 前缀（作用域内）

三大改善：① 枚举器不泄漏（在 Color 的作用域内，不同 enum 可同名）；② 不与整数隐式比较/转换（color == fruit 直接编译错误）；③ 需要整数值时显式 static_cast。

✅ 最佳实践（原文）

优先 enum class，避免非限定 enum。枚举器的典型用途：游戏状态（loading/playing/paused）、选项集合、错误码。

结构体（struct）：数据打包

📐 概念：struct 与成员变量

结构体：把多个相关变量打包成一个自定义类型：

struct Employee
{
    int id{};
    int age{};
    double wage{};
};  // 分号！

Employee joe{ 1, 25, 50000.0 };  // 聚合初始化（按成员顺序）
joe.age = 26;                    // 成员选择运算符 . 访问

1.7 课身高排序"名字和身高必须一起移动"的痛点在此解决：一个 Employee 就是一个整体，swap 一次全带走。

struct + 函数：按引用传递自定义类型

void printEmployee(const Employee& e)   // const 引用：只读不拷贝
{
    std::cout << e.id << " is " << e.age << '\n';
}

void promote(Employee& e)               // 非 const 引用：要改它
{
    ++e.age;
    e.wage *= 1.05;
}
✅ 选型规则（原文）
  • struct 通常按 const 引用传递（避免拷贝整个结构）；
  • 需要修改就按非 const 引用；
  • 特别小的 struct（两三个基本类型成员）按值也可以。

判断① "两个不同的非限定枚举，它们的枚举器如果同名会冲突。"

判断② "enum class 的枚举器可以直接和整数比较。"

预测③ 输出什么？

struct Point { int x{}; int y{}; };

void move(Point& p, int dx, int dy)
{
    p.x += dx;
    p.y += dy;
}

int main()
{
    Point pos{ 1, 2 };
    move(pos, 3, 4);
    std::cout << pos.x << ',' << pos.y;
}
💭 思维转变：从"基本类型的搬运工"到"类型的作者"

前 11 章你是基本类型的使用者；本章起你是类型的作者。枚举把"魔法数字"（0/1/2 表示状态）变成有名字的合法值集合；struct 把散落的相关变量聚合成有意义的整体。两者都是 1.5 课"名字要达意"在类型层面的延伸——类型即文档。下一章的类会进一步把"数据+操作"打包；但 struct 打包数据的能力在纯数据场景永远是首选（原文：数据成员聚合，行为很少时用 struct）。
