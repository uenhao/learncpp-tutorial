14.1 类与封装：从 struct 到 class

struct 会打包数据（13 课），但打包出来的整体没有"纪律"：分母可以是 0，首字母可以和名字对不上。本课引入 class——把数据和操作绑成一个整体，并给成员上访问控制，让非法状态进不来。（原文 14.1–14.8）

面向对象编程（OOP）：数据自己会"做事"

📐 概念：过程式 vs 面向对象

过程式编程：函数（functions）和数据是分离的实体，靠程序员手动组装；面向对象编程（OOP）：聚焦"同时包含 properties（性质=数据）与 behaviors（行为=操作）"的自定义类型。两种视野下的同一件事：

eat(you, apple);   // 过程式：函数吃数据，数据被传来传去
you.eat(apple);    // OOP：对象自己会吃，操作长在类型上

OOP 不取代过程式，而是多一件工具。注意术语："object" 在 C++ 里通常仍指"一段能存值的内存"（1.2 课），OOP 语境下的对象可专称 class object。

选择① 动物园要新增一种动物 Snake（名字+腿数）。过程式版本用 enum AnimalType + 每个函数里 switch；OOP 版本每个动物一个类型。哪种设计对已有代码的改动最小？

class invariant：struct 守不住的纪律

📐 概念：类不变式（class invariant）

类不变式 = 必须在对象的整个生命周期内为真、使对象保持有效状态的条件。违反不变式的对象处于 invalid state，继续使用可能得到意外结果甚至未定义行为。

struct Fraction
{
    int numerator { 0 };
    int denominator { 1 }; // 不变式：分母永远不能是 0
};

Fraction f { 5, 0 };   // ❗ 编译器不拦：struct 只是数据打包
printFractionValue(f); // 运行时才炸：除以零

更隐蔽的例子：firstInitial 应始终等于 name 的首字符——两个成员的相关性也是一种不变式，靠使用者"记得同步"迟早出事。9 课的 assert 能文档化不变式，但正确的做法是在赋坏值的地方拦截，而不是在用坏值的地方断言。

判断② "minMax struct 的不变式是 min <= max——这条纪律不能只靠使用者自己小心来维护。"

成员函数（member functions）：操作长在类型上

📐 概念：成员函数与隐式对象

成员函数 = 属于某个 class type（struct/class/union 都算）的函数；它必须定义在类型定义内部，并且必须通过该类型的对象来调用。调用时所作用的那个对象叫隐式对象（implicit object）：

struct Date
{
    int year {};
    int month {};
    int day {};

    void print()   // 成员函数
    {
        std::cout << year << '/' << month << '/' << day; // 未加前缀的成员 → 隐式对象
    }
};

Date today { 2020, 10, 14 };
today.print();      // today 是隐式对象，print 操作的是它

对比：非成员函数（free function）显式传对象、显式访问成员；成员函数隐式传对象（背后是 15 章的 this 指针）、隐式访问成员。函数体里没加 . 前缀的成员标识符，全部关联到隐式对象。

预测③ 输出什么？（joe 和 kate 都是 Person）

struct Person
{
    std::string name{};

    void kisses(const Person& person)
    {
        std::cout << name << " kisses " << person.name << '\n';
    }
};

// joe.name == "Joe", kate.name == "Kate"
joe.kisses(kate);
⚠️ 类内可以乱序使用，但成员按声明顺序初始化

类定义内部不要求先声明后使用：成员变量/函数可以任意顺序互相引用（编译器对类内函数做了隐式前向处理）。但有一条铁律：数据成员按声明顺序初始化——若 int m_bad1 { m_data }; 写在 m_data 声明之前，读到的是尚未初始化的内存（未定义行为）。所以别在默认成员初始化里引用其他成员。

const 对象与 const 成员函数

📐 概念：const member function

对象也可以是 const（创建时必须初始化）。const 对象不能改 public 成员，也不能调用非 const 成员函数——哪怕那个函数根本不改成员。const 成员函数 = 在参数列表后、函数体前加 const，承诺不修改对象、不调用任何非 const 成员函数：

struct Date
{
    int year {}; int month {}; int day {};

    void print() const   // ← const 成员函数
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

const Date today { 2020, 10, 14 };
today.print();  // ✅ const 对象可以调用 const 成员函数

最常踩的场景：函数按 const 引用收参数（12 课）——形参被当作 const 对象，里面调非 const 成员函数直接编译错误。所以：不改对象状态的成员函数一律标 const（加了以后再摘掉，会破坏所有在 const 对象上调用它的代码）。

public / private：访问控制

📐 概念：访问级别与 class 的默认行为

每个成员都有访问级别：public（类外的任何代码都能访问）/ private（只有同类成员能访问）。关键差异：

class Date   // class：成员默认 private
{
    int m_year {};   // private by default
    int m_month {};
    int m_day {};

    void print() const { /* ... */ } // 也默认 private！
};

Date today { 2020, 10, 14 }; // ❌ 编译错误：有 private 成员后
                             //    不再是 aggregate，聚合初始化失效
  • struct 默认 public，class 默认 private——这是两者唯一的技术差异；
  • 有 private 成员 → 不是 aggregate → 13 课的聚合初始化用不了 → 这正是下一课构造函数的动机；
  • private 数据成员惯用 m_ 前缀（member），区分成员与参数/局部变量；
  • 访问级别是 per-class（按类）而非 per-object（按对象）。

判断⑤ "Person 的成员函数里，可以直接访问另一个 Person 对象参数的 private 成员（如 p.m_name）。"

访问函数（access functions）：getter 与 setter

📐 概念：getter / setter

访问函数 = 只为读/写单个 private 成员而存在的 public 成员函数：getter（读，通常 const）与 setter（写，必须非 const）：

class Date
{
    int m_year { 2020 }; // m_ 前缀还避免了与 getter 同名（C++ 不允许同名）

public:
    int getYear() const        { return m_year; }
    void setYear(int year)     { m_year = year; }
};

getter 返回便宜类型按值返回；返回昂贵类型（如 std::string）按 const std::string& 返回避免拷贝（注意：别返回成员的非 const 引用——外部 f.value() = 5 就绕过了访问控制）。实务建议：没有不变式却需要大量 getter/setter 的类型，直接用 struct + 公开成员可能更诚实；优先实现"行为"（如 kill()/revive()）而不是裸的 setAlive(bool)。

数据隐藏（封装）：为什么要藏起来

📐 概念：interface 与 implementation

接口（interface） = 类的 public 成员构成的公共契约，改了就破坏使用方；实现（implementation） = 成员变量 + 函数体，随便改。数据隐藏（data hiding） = 把实现藏进 private、强迫外界只走接口。收益（原文）：

  1. 类能自己维护不变式——所有修改走接口，联动自动完成；
  2. 更好的错误检测——在接口内校验参数，坏值进门就被拦；
  3. 改实现不破坏使用方——接口不变，成员从单值换成数组都行；
  4. 更易调试——修改入口唯一，断点只打一处。

判断⑥ "一个类型没有不变式，却需要一大堆 getter/setter 才能被外界使用——这时候也许直接用 struct（公开成员）更合适。"

✅ 最佳实践（原文）
  • class 的成员变量一般 private、成员函数一般 public；struct 一般不加访问说明符（全员 public）；
  • 不改（也永远不会改）对象状态的成员函数 → 标 const；
  • 能用非成员函数就别用成员函数（如 print(const Yogurt&)）：不属于接口、强迫走公共接口、可携带应用特有逻辑；
  • 声明顺序：public 在前，private 在后。
💭 思维转变：封装 ≠ "藏起来"，而是"守门"

13 课的 struct 是"透明的数据袋"；本课的 class 是"有保安的仓库"：不变式写在类型里，所有修改必须过接口这道门——非法状态无法被构造出来，而不是出了错再排查。下一课解决"对象出生"这一步：有 private 成员后聚合初始化失效了，谁给对象一个合法的出生方式？答案是构造函数。
