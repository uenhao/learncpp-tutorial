14.2 构造函数：对象出生的那一刻

上一课的悬念：成员变成 private 后，聚合初始化失效了——谁负责给对象一个合法的出生方式？构造函数（constructor）：对象创建时自动调用的特殊成员函数，让"出生即合法"成为现实。（原文 14.9–14.13）

构造函数基础

📐 概念：constructor（构造函数）

非 aggregate 类型的对象创建后自动调用的成员函数。规则：

  • 名字与类同名，没有返回类型（连 void 都不写）；
  • 通常 public（属于接口）；编译器按参数匹配：找到匹配的构造函数 → 先分配内存再调用它；找不到 → 编译错误；
  • aggregate 不能有构造函数（加了就不再是 aggregate）。
class Foo
{
    int m_x {};
    int m_y {};

public:
    Foo(int x, int y)   // 与类同名、无返回类型
    {
        std::cout << "Foo(" << x << ", " << y << ") constructed\n";
    }

    void print() const
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ")\n";
    }
};

Foo foo{ 6, 7 };  // 调用 Foo(int, int)

Key insight：构造函数并不创建对象。编译器先完成内存分配，构造函数在"未初始化的对象"上被调用；但没有匹配的构造函数，对象根本无法创建。另外构造函数不能标 const（它要初始化成员——const 在构造完成后才对对象生效，所以 const 对象也能调构造函数）。

预测① 上面这个类执行 Foo foo{ 6, 7 }; foo.print();，print() 输出什么？

判断② "构造函数不能是 const 成员函数。"

成员初始化列表（member initializer list）

📐 概念：member initializer list

构造函数参数之后、以 : 开头、逗号分隔的成员初始化序列——这才是真正的初始化：

Foo(int x, int y)
    : m_x { x }        // 冒号开头，直接初始化形式
    , m_y { y }        // 按声明顺序书写；列表末尾没有分号
{
    // 函数体：列表执行完才轮到这里（做 setup，不再初始化）
}
  • 成员用直接初始化形式（推荐花括号）；等号 copy initialization 在这里不行；
  • 函数体里写 m_x = x; 是赋值不是初始化——const 成员、引用成员会直接编译失败；
  • Key insight：列表执行完 → 对象 initialized；函数体执行完 → 对象 constructed；
  • 优先级：初始化列表 > 默认成员初始化器（13 课的 int m_x{}）> 无初始化（fundamental 类型未初始化 = UB，4 课的老朋友）。
⚠️ 初始化顺序由声明决定，不由列表书写顺序决定

成员永远按类内声明顺序初始化。下面这个构造函数想先算出 m_y 再用它初始化 m_x——但 m_x 声明在前，先初始化，读到的 m_y 是未初始化的垃圾值：

Foo(int x, int y)
    : m_y { std::max(x, y) }  // 列表里先写 m_y？
    , m_x { m_y }             // 实际 m_x 先初始化——m_y 还没值！

所以最佳实践：列表按声明顺序书写，并且尽量不用其他成员的值来初始化成员（彻底消除顺序依赖）。

选择③ 成员初始化列表里，成员的实际初始化顺序由什么决定？

判断④ "成员初始化列表支持等号写法：Foo(int x) : m_x = x { }。"

默认构造函数与默认实参

📐 概念：default constructor（默认构造函数）

不接受任何参数的构造函数（全部参数都带默认实参的也算）。有它，Foo foo{}（value initialization，推荐）和 Foo foo; 都会调用它。三个要点：

// ① 全默认实参的构造函数 = 默认构造函数
Foo(int x = 0, int y = 0) : m_x { x }, m_y { y } {}

// ② 一个类只能有一个默认构造函数——否则二义性！
Foo() {}                      // 无参版
Foo(int x = 1, int y = 2) {}  // 全默认实参版
Foo foo{};  // ❌ compile error: ambiguous

// ③ 显式要求编译器生成默认版：= default
Fraction() = default;   // 成员走各自默认初始化（0/1）

= default 与空函数体 {} 的差别：value initialization 时前者先零初始化再走默认成员初始化器，后者什么都不做（没写默认初始化器的成员保持未初始化）。只要你给所有成员都写了默认初始化器（一直以来的习惯），差异就不存在。什么时候该有默认构造函数？——"全默认值创建对象有意义"才提供（Fraction 0/1 有意义；Employee 无名无意义，别提供，让编译器替你拦住无效对象）。

委托构造函数（delegating constructors）

📐 概念：constructor delegation（构造函数委托）

构造函数可以在初始化列表里调用同类另一个构造函数，把初始化工作委托出去（constructor chaining）。常见模式：参数少的委托给参数多的。

Employee(std::string_view name)
    : Employee{ name, 0 }   // ✅ 委托：在初始化列表里调用
{
}

两条铁律：① delegate or initialize, not both——委托的构造函数自己的列表里不能再初始化成员；② 在函数体里"调用构造函数"不是委托——那会创建一个临时对象，跟 this 无关。

预测⑥ 三参构造函数在函数体里写了 Employee(name, id); 想复用两参构造。沿用本课 demo 的 Employee 类（成员默认初始化 m_name{ "???" }、m_id{ 0 }），执行后 e2.m_name 是什么？

Employee(std::string_view name, int id, bool isManager)
    : m_isManager { isManager }
{
    Employee(name, id); // "这行想初始化 m_name 和 m_id"
}
⚠️ 互相委托 = 无限循环

A 委托 B、B 又委托 A → 无限循环直到栈溢出。确保委托链最终落到一个"真正初始化成员"的构造函数上。

临时对象（temporary objects）

📐 概念：temporary（temporary/anonymous object）

没有名字、只存在于单个 full expression 期间的对象。创建临时对象的三种写法：

IntPair p { 1, 2 };   // 有名对象
IntPair { 1, 2 };     // 临时对象（list initialization）
print({ 7, 8 });      // 编译器把 { 7, 8 } 转换成临时对象（匹配形参类型）

临时对象是 rvalue（12 课）：只能在接收 rvalue 的地方使用；在创建点生成，full expression 结束即销毁。函数按值返回（return { 7, 8 };）返回的也是临时对象。

⚠️ 圆括号的重重陷阱：看到括号 ≠ 看到对象

圆括号被太多语法共用（函数调用、直接初始化、C 风格转换、分组、变量定义）：

Foo(1, 2);   // ≈ Foo{1, 2}：创建临时对象（然后丢弃）
Foo();       // value-initialized 临时对象
Foo(bar);    // ❗ 这不是临时对象——是【定义名为 bar 的 Foo 变量】！
             //    bar 已存在则重定义错误

看到花括号一定是对象。那上面的 Employee(name, id); 为什么是真临时对象？——带两个实参的形式解析不成变量声明，只能当表达式求值；而单参形式能被解析成"圆括号包裹声明符的声明"（Foo(bar); ≡ Foo bar;），这正是 most vexing parse 家族。转换选型：转 fundamental 类型用 static_cast；转 class 类型用 list-initialized 临时对象（std::string { sv }）；别用 C 风格转换（std::string(sv) 外观几乎相同但危险）。

💭 思维转变：初始化从"步骤"变成"语义"

到本课为止，你已经把 C++ 的初始化拼图集齐了大半：默认成员初始化器（13 课）→ 构造函数 → 成员初始化列表（本课）。它们共同保证一件事：对象在出生点就合法——而不是"先造出来，再补丁式地 set 成合法"。下一课处理对象"转手"时的最后一环：拷贝与类型转换。
