14.3 拷贝、explicit 与 constexpr：对象转手的最后一环

对象出生即合法（14.2 课）还不够——对象还会被拷贝（按值传参/返回）、被隐式转换出来、在编译期求值。本课补齐这三个"转手"场景，本章收官。（原文 14.14–14.17）

拷贝构造函数（copy constructor）

📐 概念：copy constructor

用同类型的已有对象初始化新对象的构造函数。你不写，编译器自动生成一个 public 隐式版本，做 memberwise initialization（逐成员用对应成员初始化）——通常这正是你想要的：

Fraction(const Fraction& f)   // 参数必须是 (const) 左值引用
    : m_numerator{ f.m_numerator }    // per-class 访问：能读 f 的 private
    , m_denominator{ f.m_denominator }
{
}
  • 按值传参：实参拷贝进形参 → 隐式调用拷贝构造；按值返回：用返回值初始化临时对象 → 同样调用；
  • 不想要拷贝？Fraction(const Fraction&) = delete;（比 private 版更好——private 只是外部调不到，类内仍可拷贝）；
  • 浅拷贝问题（动态内存的类需要自定义拷贝构造）在第 21 章展开；rule of three：需要自定义拷贝构造/析构/拷贝赋值之一，大概率三个都需要。

选择① 拷贝构造函数的参数为什么必须是引用，不能按值 Fraction(Fraction f)？

判断② "类不写拷贝构造函数时，编译器会自动生成一个 public 的、逐成员拷贝的隐式版本。"

初始化形式与 copy elision（拷贝省略）

📐 概念：六种初始化形式，三个关键差异

class 类型的十种初始化写法（Foo f1; / Foo f2{} / Foo f3 = 3; / Foo f4(4); / Foo f5{ 5 }; / Foo f6 = { 6 }; / Foo f7 = f3; / Foo f8(f3); / Foo f9{ f3 }; / Foo f10 = { f3 };）本质上都在初始化对象、都走构造函数重载解析。三个关键差异值得记住：

  1. List initialization 禁止窄化转换（10 课：Foo f5{ 4.9 } 若 Foo(int) 则编译错误）；
  2. Copy initialization（等号）只考虑非 explicit 构造函数（下一节）；
  3. List initialization 优先匹配 list constructors（16 章容器）；另外成员初始化列表里只能用直接初始化形式。
📐 概念：copy elision（拷贝省略）

编译器省掉不必要的对象拷贝的优化——它是 as-if 规则的唯一例外（5 课）：即使拷贝构造有副作用（打印）也可以被省略，所以拷贝构造函数不应有拷贝以外的副作用。C++17 起部分场景（如返回纯临时对象、用临时对象初始化同名对象）强制省略——连优化开关都不用开；命名返回值（NRVO）则由编译器自行决定。

Something s { Something { 5 } }; // C++17 起等价于 Something s { 5 };
                                 // 拷贝构造一次都不调用！

预测③ 拷贝构造函数里打印 "Copy constructor called"。执行 Something s { Something { 5 } };（C++17），这句话打印了几次？

转换构造函数与 explicit

📐 概念：converting constructor 与 explicit

默认所有构造函数都是 converting constructors——可被用于隐式转换。这既是便利也是事故源：

class Dollars
{
    int m_dollars{};

public:
    /* explicit */ Dollars(int d) : m_dollars{ d } {}
};

void print(Dollars d) { /* ... */ }

print(5);              // 不加 explicit：int 隐式转换成 Dollars——通过！
print(Dollars{ 5 });   // 加了 explicit：直接构造仍然 OK
print(5);              // 加了 explicit：编译错误 ✅
  • 一次隐式转换最多应用一个 user-defined conversion：printEmployee("Joe") 需要 C 串→string_view→Employee 两跳，编译失败；修法："Joe"sv 或显式 Employee{ "Joe" }；
  • explicit 构造函数不能用于 copy initialization / 任何隐式转换，但 direct initialization、direct list initialization、static_cast 都可以用。
✅ 最佳实践（原文）

单参数构造函数默认标 explicit；仅当"两种类型语义等价且转换高效"时才考虑放开（如 string_view 的 C 串构造函数）。拷贝/移动构造函数永远不要 explicit——它们不做类型转换。

选择④ Dollars(int) 标了 explicit 后，下列哪个能编译？

constexpr 与类

📐 概念：literal type 与 constexpr 类

成员函数（含构造函数）可以标 constexpr，从而能在编译期求值。对象要 constexpr，其类型必须是 literal type：基本类型、引用、多数 aggregate（13 课 struct 天生支持）、以及有 constexpr 构造函数的类：

class Pair
{
    int m_x {};
    int m_y {};

public:
    constexpr Pair(int x, int y) : m_x { x }, m_y { y } {}  // 构造函数 constexpr

    constexpr int greater() const { return (m_x > m_y ? m_x : m_y); }
};

constexpr Pair p { 5, 6 };        // 编译期构造
constexpr int g { p.greater() };  // 编译期求值 → 6
  • 编译期求值链上每个环节都要 constexpr：非 aggregate 类的构造函数、被调用的成员函数；
  • C++11 的 constexpr 成员函数隐式 const，C++14 起不再隐式——要 const 就显式写；
  • constexpr ≠ const：constexpr 是"能在编译期确定值"，const 是"运行期不可改"。

判断⑤ "想让类对象出现在常量表达式中（如 constexpr Pair p{5,6};），只要成员函数标 constexpr 就够，构造函数不用标。"
