15.1 this 指针、头文件与嵌套类型：类的骨架

14 章你造出了类。本课给类装上三个"骨架件"：this 指针（成员函数怎么知道在操作谁）、头文件组织（类怎么跨文件生长）、嵌套类型（类型也是类的成员）。（原文 15.1–15.3）

隐藏的 this 指针

📐 概念：this = 指向隐式对象的 const 指针

每个非静态成员函数内部都有关键字 this——一个 const 指针（指针本身不可改指向），保存着隐式对象的地址。编译器把调用和定义都做了改写：

simple.setID(2);
// 编译器改写成：
Simple::setID(&simple, 2);          // 对象变成按地址传递的实参！

// 成员函数定义被改写成：
static void setID(Simple* const this, int id)
{
    this->m_id = id;   // 裸写的 m_id 是 this->m_id 的简写
}

Key insight：所有非静态成员函数都有 this。两个推论：① this 是函数参数而非成员——不占对象的内存，也不存在"每个对象各一份"；② const 成员函数的 this 是"指向 const 的 const 指针"——14.1 课"const 对象不能调非 const 成员函数"的底层原因：那需要把 pointer-to-const 转成 pointer-to-non-const，丢 const，拒绝。另外 this 永远指向隐式对象，解引用前不需要判空。

判断① "this 指针是对象的一部分，所以含成员函数的类比 struct 更占内存。"

📐 概念：显式 this 的两个正经用途
// 用途一：参数遮蔽成员时消歧（struct 没用 m_ 前缀的场合）
void setData(int data)
{
    this->data = data;  // this->data 是成员，data 是参数
}

// 用途二：链式调用——返回 *this 的引用
Calc& add(int value) { m_value += value; return *this; }
Calc& sub(int value) { m_value -= value; return *this; }

// 于是：
calc.add(5).sub(3).mult(4);   // 每次返回 calc 自己，继续点下去

链式调用的原理与 std::cout << "a" << "b" 完全相同（operator<< 返回流对象本身；若返回 void，void{} << "b" 就点不下去了）。重置对象到默认状态也别直接"调用构造函数"（14.2 课的临时对象陷阱）：用 void reset() { *this = {}; }——造一个默认对象整体赋值过来。

预测② Calc calc{};，成员初值 0。执行 calc.add(5).sub(3).mult(4); 后 calc.getValue() 是多少？

✅ 最佳实践（原文）

不要给所有成员显式加 this->——降低可读性。private 成员用 m_ 前缀区分（14 章的约定）比到处写 this-> 干净；显式 this 只留给"参数遮蔽成员"和"返回 *this"两个场景。

类与头文件：类的多文件组织

📐 概念：类内声明，类外定义

类变大后，成员函数在类内只留声明（原型），实现放到类外，定义时用 Date:: 前缀（作用域解析符）标明归属：

class Date
{
    int m_year{}; int m_month{}; int m_day{};

public:
    Date(int year, int month, int day); // 声明
    void print() const;                 // 声明
    int getYear() const { return m_year; } // trivial 函数留在类内
};

Date::Date(int year, int month, int day)   // 定义：Date:: 前缀
    : m_year{ year }, m_month{ month }, m_day{ day }
{
}

void Date::print() const
{
    std::cout << "Date(" << m_year << ", " << m_month << ", " << m_day << ")\n";
}

组织方式（与 2.5 课函数的拆分一脉相承）：类定义放同名 header，非 trivial 成员函数放同名 .cpp（必须参与编译，链接器才能接上）。为什么 header 里放完整类定义而不是前置声明？——编译器要用类型就得知道成员和对象大小，类的"前置声明"不够用。

⚠️ ODR 与类：类型豁免，但同一文件两次包含不豁免

2 章讲过 ODR（每程序一个定义）。对类有一条特殊豁免：类定义本身可以出现在多个 .cpp 里（不然谁都写不了多文件程序）。但同一个 .cpp 里包含两次类定义仍是违规——所以 header 还是要有 header guard（2.6 课）。Key insight：类内定义的成员函数隐式 inline（7.4 课），被多个文件包含不违反 ODR；类外定义的不隐式 inline，要放 header 就得手动标 inline。默认实参永远写在类定义里（成员函数总随类定义一起声明）。

选择③ 在类外定义成员函数 print，正确的写法是？

判断④ "Date.h 在同一个 .cpp 里被 #include 两次（忘了 header guard），类定义出现 2 次——反正类型豁免 ODR，不算违规。"

嵌套类型（nested types）：类里的第三种成员

📐 概念：成员类型 / 别名 / 嵌套类

类里除了数据成员和成员函数，还能定义类型（enum、别名、类都行）——它们同样受访问控制，完全限定名是 Fruit::Type：

class Fruit
{
public:
    enum Type            // 嵌套【非限定】enum：类已是作用域，
    {                    // 再写 enum class 就 Fruit::Type::apple 冗余了
        apple, banana, cherry,
    };

private:
    Type m_type{};
    int m_percentageEaten{ 0 };

public:
    Fruit(Type type) : m_type{ type } {}
    Type getType() const { return m_type; }
    bool isCherry() { return m_type == cherry; } // 类内：裸写 cherry
};

// 类外：必须带 Fruit:: 前缀
Fruit apple { Fruit::apple };
if (apple.getType() == Fruit::apple) { /* ... */ }
  • 类型别名也能嵌套：using IDType = int; 类内裸用、类外 Employee::IDType（标准库大量使用——std::string 定义了十来个）；
  • 嵌套类没有外部类的 this，不能直接摸外部类成员；但作为外部类的成员，可以访问外部类作用域的 private（通过传入的对象）——标准库容器的 iterator 通常是嵌套类；
  • 嵌套类型必须先完整定义再使用 → 定义在类顶部。

选择⑤ Type 是 Fruit 里嵌套的非限定 enum，类外怎么判断"是不是苹果"？

💭 思维转变：成员函数"属于类"的三层含义

本课把"成员函数属于类"讲透了：调用层——隐式对象被编译器转成 &object 实参（this 的秘密）；组织层——类是作用域（Date:: 前缀、嵌套类型、嵌套枚举器）；链接层——类内定义隐式 inline、类外定义要 Date:: 标归属（ODR 的类型豁免撑起多文件工程）。下一课处理对象的生命周期终点与"全体共享"的静态成员。
