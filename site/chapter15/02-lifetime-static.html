15.2 析构函数与静态成员：对象的终点与"全体共享"

构造函数管出生（14.2 课），本课补上终点——析构函数；再给类装上"不属于任何对象"的成员——静态成员（变量与函数），顺带让类模板长出成员函数。（原文 15.4–15.7）

析构函数（destructor）：销毁前的最后机会

📐 概念：destructor

非 aggregate 类对象销毁时自动调用的成员函数，用于清理（释放资源、发数据、写日志）。规则：名字 = 类名前加波浪号 ~；不能带参数、无返回类型；一个类只能有一个：

class Simple
{
    int m_id{};

public:
    Simple(int id) : m_id{ id }
    {
        std::cout << "Constructing Simple " << m_id << '\n';
    }

    ~Simple()   // 析构函数
    {
        std::cout << "Destructing Simple " << m_id << '\n';
    }
};

价值：把"清理"从使用者的责任里拿走。15.4 课的动机案例——网络缓冲类要在退出前把数据发出去，靠使用者记得调 sendData() 不可靠（提前 return 的路径就漏了）；放进析构函数，每条退出路径都自动清理。析构函数可以安全调用其他成员函数——对象在析构函数执行完之后才被销毁。一般不要显式调用析构函数（自动的、也几乎不存在"清理两次"的合理场景）。

预测① 程序如下。Simple simple1{1} 在 main 顶层，Simple simple2{2} 在内层块。输出的第 3 行是什么？

int main()
{
    Simple simple1{ 1 };
    {
        Simple simple2{ 2 };
    } // ← 这里
    std::cout << "...main body...\n";
    return 0;
}

判断② "std::exit() 退出程序前会先调用所有局部对象的析构函数。"

类模板的成员函数

📐 概念：模板参数进入类

11 章的函数模板升级成类模板：typename T 既能当数据成员类型，也能当成员函数的参数/返回类型。类内定义的成员函数自动继承类的模板参数声明：

template <typename T>
class Pair
{
    T m_first{};
    T m_second{};

public:
    Pair(const T& first, const T& second)   // 类内：直接用 T
        : m_first{ first }, m_second{ second } {}

    bool isEqual(const Pair<T>& pair);      // 只声明
};

// 类外定义：必须重新提供 template 声明 + 全模板名 Pair<T>::
template <typename T>
bool Pair<T>::isEqual(const Pair<T>& pair)
{
    return m_first == pair.m_first && m_second == pair.m_second;
}

Pair p1{ 5, 6 };  // CTAD：非 aggregate 类不需要推导指引，构造函数就够了
  • injected class name：类作用域内，Pair 就是 Pair<T> 的简写——所以构造函数叫 Pair 不带 <T>；类外定义的参数也可以写 const Pair&；
  • 模板隐式实例化的函数隐式 inline → 模板成员函数定义放 header（类定义正下方）不违反 ODR（15.1 课规则的模板版）；
  • 对照 11 章：struct 版 Pair 聚合初始化 + 手写推导指引；class 版（非 aggregate）靠构造函数，CTAD 自动工作。

选择③ 模板类 Pair<T> 的成员函数 isEqual 在类外定义，正确写法是？

静态成员变量：全体对象共享一份

📐 概念：static member variable

static 成员变量被类的所有对象共享，而且没有任何对象时也存在（程序启动创建、结束销毁）。Key insight：静态成员 = 住在类作用域里的全局变量（7.3 课"全局之恶"的受控版——至少有访问控制和类命名空间）：

class Something
{
    // C++17 首选：static inline 让静态成员直接在类内定义+初始化
    static inline int s_idGenerator{ 1 };
    int m_id{};

public:
    Something() : m_id{ s_idGenerator++ } {}  // 每个对象领一个唯一 ID
    int getID() const { return m_id; }
};

Something a{}; Something b{};
// a.getID() == 1, b.getID() == 2 —— 共享的生成器在起作用
  • 访问：最佳实践用 Something::s_value（经对象也能访问，但不推荐——看不出是共享的）；
  • 不用 inline/constexpr 的旧写法：类内声明 ≠ 定义，要在类外全局作用域补 int Something::s_value{ 1 };（定义不受访问控制约束——private 的也能在类外定义，"定义"不算"访问"；定义放同名 .cpp，别放 header，否则多次包含 = 多个定义 = 链接错误）；
  • 类内直接初始化的三种合法姿势：static const int（仅整型/枚举）、static inline（C++17，任意类型，首选）、static constexpr（隐式 inline）；
  • 冷知识：只有静态成员允许 auto 推导和 CTAD——非静态成员不允许。

判断④ "private 的静态成员变量不能在类外定义（毕竟外面访问不了它）。"

静态成员函数：不属于任何对象

📐 概念：static member function

不关联任何对象、直接用类名调用的成员函数（经对象调用也合法但不推荐）。两个特性：

class IDGenerator
{
    static inline int s_nextID{ 1 };

public:
    static int getNextID() { return s_nextID++; }  // 无 this、只碰静态成员
};

int IDGenerator::getNextID() ... // 类外定义：不重复写 static
  • 没有 this 指针（没有隐式对象——15.1 课机制的必然结果）；
  • 能直接访问静态成员（变量/函数），不能访问非静态成员（非静态成员必须属于某个对象）；
  • 类外定义的写法同普通成员函数（IDGenerator::getNextID()），定义处不重复 static；放 header 要标 inline。

判断⑤ "静态成员函数里既没有 this，也不能访问类的非静态数据成员。"

⚠️ 全静态类（monostate）：慎用，以及"没有静态构造函数"

成员全 static 的类叫 pure static class——本质是把全局变量/全局函数包了个名字，7.3 课的坏处全带上（无法造两个独立实例、隐式耦合）。和 namespace 的区别只有一条：类有访问控制。有静态数据 + 需要访问控制 → 用类；否则 → namespace。另外 C++ 没有静态构造函数：能直接初始化就在定义点初始化；需要执行代码才能初始化的，用一个（static）函数造好对象再拷给静态成员。

💭 思维转变：从"对象的一生"到"类型的一生"

构造/析构函数管住单个对象的生与死；静态成员是类型级的存在——不随对象生灭，全体共享。前者是"每个员工一张工牌"（成员），后者是"公司共用一部总机"（静态）。14 章的 class invariant 是"每个对象各自合法"；静态成员提醒你还有另一类不变式："全体对象合计合法"（如 ID 不重复）。下一课：friend——给封装开一扇受控的门。
