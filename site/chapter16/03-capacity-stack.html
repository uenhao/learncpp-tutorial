16.3 容量与栈行为：vector 的"动"从哪来

vector 叫动态数组：长度能在运行期变。本课拆开"动态"的引擎盖看两件事——length 与 capacity 为何分开记账，以及元素个数未知时怎么用栈行为优雅地装数据；最后看看 std::vector<bool> 这个著名的"伪容器"。（原文 16.10–16.12）

length 与 capacity：两本账

📐 概念：length vs capacity / reallocation

length（size）= 当前在用的元素数；capacity = 已分配存储能容纳的元素数。类比：length 是蛋盒里装了的鸡蛋，capacity 是蛋盒的格数。Key insight：length 是"在用"，capacity 是"已分配"——分开记账才能在 length 变化时免于重新分配。

std::vector v{ 0, 1, 2 };
v.resize(5);        // 变长：保留 0 1 2，新增元素 value-initialized（0）
                    // → 0 1 2 0 0
v.resize(3);        // 变短：截断，capacity 不减
v.resize(5);        // 再变长：capacity 够用 → 零重新分配！

reallocation（重新分配）：容量不足时的三步——申请新内存、把旧元素拷/移过去、归还旧内存。因为要搬每个元素，reallocation 是昂贵的，要避免。缩小不还内存；shrink_to_fit() 只是"请求"（非绑定，实现可不理）。⚠️ 铁律：有效下标基于 length，不是 capacity——capacity 5、length 3 时 index 3、4 照样越界！

判断① "capacity 是 5、length 是 3 的 vector，访问下标 4 合法——毕竟内存已经分配了。"

预测② std::vector v{ 0, 1, 2 }; 执行 v.resize(5); 后遍历打印 v，输出什么？

栈行为：元素个数未知时的正确姿势

📐 概念：stack（LIFO）与 vector 的栈接口

"用户会输多少个数"事先不知道——预设上限（30 个？太少太多都尴尬）、先问个数再建（让用户数数？）、动态扩容逻辑（和业务逻辑搅在一起）都是坏方案。正确姿势：栈（stack）——插入删除都在同一端、后进先出（LIFO）。C++ 不造独立栈容器，而是给 vector 这类容器加栈操作：

std::vector<int> stack{};

stack.push_back(1);   // push：压入尾部（length +1，必要时 reallocation）
stack.push_back(2);
stack.push_back(3);
stack.back();         // peek/top：看栈顶（3），不移除
stack.pop_back();     // pop：弹出栈顶（返回 void）

// 标准场景：读到 -1 为止，全程无计数、无索引、无长度管理
while (true) {
    int x{}; std::cin >> x;
    if (x == -1) break;
    stack.push_back(x);
}
  • reallocation 增长策略因编译器而异：GCC/Clang 翻倍，VS2022 ×1.5——多分一点，避免下次 push 立刻再分配；
  • reserve(n)：只增 capacity、不动 length。栈场景先 reserve 预估容量，push 全程零 reallocation；
  • ⚠️ resize 不是为栈准备的：括号定长初始化（和 resize()）会同时设置 capacity 和 length——std::vector<int> stack(3) 让栈底压着 3 个 0，之后 push 全排在它们上面（经典错误）；
  • 口诀：用索引访问 → resize（length 得变）；用栈操作 → reserve（只要容量）。

选择③ 预计要 push 约 1000 个数进空 vector，想避免反复 reallocation。该用？

判断④ "back() 返回栈顶元素并把它从 vector 里移除。"

📐 概念：push_back vs emplace_back
Foo f{ "a", 2 };
stack.push_back(f);     // 已有对象：两者等价，prefer push_back
stack.emplace_back(f);

stack.push_back({ "a", 2 });  // 需要临时对象：先造临时再移入
stack.emplace_back("a", 2);   // 把参数转发进容器【就地构造】，免拷贝更高效

stack.push_back({ 2 });  // ❌ 编译错误：Foo(int) 是 explicit
stack.emplace_back(2);   // ✅ emplace_back 会用 explicit 构造函数

Best practice：要新建临时对象入容器（或需要 explicit 构造函数）→ emplace_back；其余 → push_back。emplace_back 更高效也更危险（容易意外触发转换构造），已有对象时没必要用它。

std::vector<bool>：最著名的"伪容器"

📐 概念：vector<bool> 特化（specialization）

std::vector<bool> 是类模板特化：可能把 8 个 bool 压进 1 个字节省空间。听着美好，代价三连：

  1. vector 对象自身开销不小（sizeof 约 40 字节）——bool 少于几十个根本省不到；
  2. 性能高度依赖实现（规范不强制优化做好）；
  3. 最要命：它不是 vector、不存 bool、不符合 C++ 容器定义——返回的是代理对象而非真正的 bool&，对其他元素类型成立的代码（T& first = v[0];）到它这里直接编译失败。

Best practice：避免 std::vector<bool>。替代：编译期已知位数 → (constexpr) std::bitset；要可变长 bool → std::vector<char>；要动态位集 → 第三方（如 boost::dynamic_bitset）。例外：官方 quiz 里用 std::vector<bool>(26) 做"26 字母猜没猜过"表——不依赖标准容器其他功能时可用。

判断⑤ "std::vector<bool> 与其他 vector 用法完全兼容——能拿到元素的真正引用。"
