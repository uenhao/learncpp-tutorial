17.2 C-style 数组与退化：语言内置的原始数组

std::array、std::vector 的地基是 C-style arrays——C++ 语言核心内置、无需头文件、从 C 继承的原始数组。它怪异且危险（原文原话），但老代码遍地都是，而且 12 课的指针要在这里补完最后一课。数组退化（decay）是理解它的钥匙。（原文 17.7–17.11）

C-style 数组基础

📐 概念：内置数组语法
int testScore[30] {};   // 30 个 value-init 的 int——不需要 #include 任何东西

const int prime[] { 2, 3, 5, 7, 11 }; // 全部元素给了初始化器 → 长度可省略

// 与 std::array 的差异：
// - 索引：operator[] 接受【任何整型】（signed/unsigned/枚举）→ 没有
//   官方 16.3 的符号转换索引问题；同样无越界检查
// - 不能 CTAD：元素类型必须显式写
// - 不能整体赋值：arr = { 5, 6, 7 }; 是编译错误（数组不是可赋值 lvalue）
// - sizeof(prime) 返回整个数组的字节数（5 × 4 = 20），无额外开销

长度必须 ≥ 1 的常量表达式；全量初始化时省略长度让编译器数（原文 Best practice）。部分编译器允许非常量长度——那是 C99 VLA 扩展，不是合法 C++，别用。取长度用 std::size()（C++17）/ std::ssize()（C++20），需要 <iterator>。

选择① 相比 std::vector/std::array，C-style 数组的索引有个"优势"是？

数组退化（array decay）：数组会"变成"指针

📐 概念：decay——长度信息的丢失

在大多数表达式语境中，C-style 数组被隐式转换成指向首元素的指针：

int arr[5]{ 9, 7, 5, 3, 1 };

auto ptr{ arr };                    // ptr 的类型是 int*（decay 发生了！）
std::cout << (typeid(ptr) == typeid(int*));  // true
std::cout << (&arr[0] == ptr);               // true：指向首元素
  • 不 decay 的少数场景：sizeof、typeid、&取数组地址、类成员、按引用传递；
  • Key insight：decayed 指针不知道数组多长——"decay"这个词说的就是长度类型信息的丢失；
  • 传参真相：看似按值传数组，实际传的是首元素地址（天然免拷贝）。void f(int arr[]) 与 void f(int* arr) 编译器看来一样（原文 Best practice：形参用数组语法 int arr[]，向人表明"这是退化数组"）；
  • sizeof 陷阱：函数内 sizeof(arr) 返回指针大小（8）而非数组大小——sizeof(arr)/sizeof(arr[0]) 的老 hack 因此危险；std::size(ptr) 对指针直接编译错误——这是保护不是缺陷！

判断② "C++ 里数组就是指针——arr 和 int* 是一回事。"

指针算术：下标的真面目

📐 概念：ptr[n] 就是 *(ptr + n)

指针算术：ptr + 1 返回下一个对象的地址（按所指类型步进，int* 即 +4 字节）——不是下一个内存地址。而下标的真相：

ptr[n]  ≡  *(ptr + n)     // 下标就是指针算术的简写！
arr[0]  ≡  *arr           // 加 0 步还是首元素——数组从 0 开始的真正原因

const int arr[] { 9, 8, 7, 6, 5 };
const int* ptr{ arr };        // 指向元素 0
ptr[1];   // 元素 1 → 8
ptr = &arr[3];                // 现在指向元素 3
ptr[1];   // "ptr 所指对象的下一个对象" → 元素 4 → 5
ptr[-1];  // 负索引合法：上一个对象 → 元素 2 → 7
  • Key insight：索引是相对位置不是绝对位置——ptr 指到哪，ptr[1] 就是"它下一个"；
  • Best practice：从头（元素 0）索引用下标；从某元素出发的相对定位用指针算术；
  • 遍历模式：begin 指首元素、end 指尾后（one-past-the-end），for (; begin != end; ++begin)——持有尾后地址合法（不可解引用）；18 章迭代器正是这个模式；
  • 官方 16.8 的 range-based for 底层就是这么展开的：arr 到 arr + std::size(arr)。

C-style 字符串：null terminator 的故事

📐 概念：C-style string = char 数组 + '\0'

字符串字面量 "Hello, world!" 的类型是 const char[14]——13 个字符 + 1 个隐藏的 null terminator（'\0'）。为什么要有它？——数组传参会 decay、丢长度，没有终止符函数就不知道字符串到哪结束（17.8 官方 quiz Q2 的答案）：

const char str[]{ "string" };  // 6 字符 + '\0'，数组长度 7

std::cout << str;              // 一直打印直到 '\0'（没有它 = UB！）
std::size(str);                // 7 —— 数组长度（不是字符串长度！）
std::strlen(str);              // 6 —— 字符串长度（<cstring>，慢：遍历到 '\0'）

char rolls[255] {};
std::cin.getline(rolls, std::size(rolls));  // 安全读入：最多 254 字符
  • std::size() 返回数组长度（char str[255]{ "string" } 得 255！）；std::strlen() 返回字符串长度且对 decayed 指针有效，但要逐字符数到 '\0'——慢；
  • 历史包袱：C++20 之前 std::cin >> rolls 不限长度——buffer overflow，安全漏洞的经典来源；
  • Best practice：非 const 的 C-style string 对象用 std::string 替代；符号常量（下一节）用 string_view 替代。C-style string 只在"全局 constexpr 数据"和"底层互操作"还值得出现。

判断④ "char str[255]{ "string" }; 的 std::size(str) 返回 6（字符串长度）。"

字符串符号常量：该退役的老写法

📐 概念：两种写法与 cout 的"智能"
const char name[] { "Alex" };         // 写法一：拷贝一份到数组（两份 "Alex"）
const char* const color{ "Orange" };  // 写法二：指针指向只读内存中的字面量

auto s1{ "Alex" };    // const char*（decay！）
auto& s3{ "Alex" };   // const char(&)[5]（按引用：连长度都保住）
  • 相同内容的字面量可被编译器合并成一份（省内存）；
  • cout 对 char*/const char* 特殊对待：打印字符串而非地址；其他指针打印地址。陷阱：char c{ 'Q' }; std::cout << &c;——&c 是 char* 但不是 null-terminated → UB（打印 'Q' 加一堆垃圾直到撞见 0）；想打印地址用 static_cast<const void*>(ptr)；
  • Best practice：字符串符号常量用 constexpr std::string_view 替代 C-style 写法（5 章的工具在这里正式接班）。
✅ 本章最佳实践汇总（原文）
  • 能不用 C-style 数组就不用（全局 constexpr 数组除外——语法简、索引无符号问题）；
  • 只读字符串 → std::string_view；可变字符串 → std::string；非 constexpr 数组 → std::vector；
  • 从头索引优先下标；相对定位优先指针算术；
  • C-style 数组形参用 int arr[] 语法而非 int* arr（对人是文档）。
