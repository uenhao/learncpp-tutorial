18.1 选择排序与迭代器：从手写算法到统一遍历

先亲手写一个最直观的排序算法（选择排序），看清"算法"长什么样；再引入迭代器——让"遍历"这件事对所有容器长一个样，为下一课的标准库算法铺路。（原文 18.1–18.2）

选择排序（selection sort）

📐 概念：排序与选择排序

排序 = 把数组元素按特定顺序排列。价值：①按序展示；②让查找更快（有序数组用简单算法搜 100 万元素只需约 20 次比较——二分查找的直觉）；③让某些查找变得不必要（最大值必然在端点）。但排序本身昂贵——只为了搜一两次而排序通常不划算。

选择排序（最好理解、也最慢的排序之一）：①从头扫描找最小值；②与当前位置交换；③从下一个位置重复：

for (int startIndex{ 0 }; startIndex < length - 1; ++startIndex)
{
    int smallestIndex{ startIndex };  // 先假设本轮第一个元素最小

    for (int currentIndex{ startIndex + 1 }; currentIndex < length; ++currentIndex)
    {
        if (array[currentIndex] < array[smallestIndex])
            smallestIndex = currentIndex;   // 发现更小的，记下下标
    }

    std::swap(array[startIndex], array[smallestIndex]); // 换到正确位置
}

两个细节：std::swap（<utility>）交换两个值；外层循环只走到 length - 1——走到最后一个元素时它必然已在正确位置，再比较就是自己和自己交换（冗余）。排序 std::string 数组同理，只换元素类型。

判断① "为了把查找提速，先给数组排个序总是值得的。"

预测② { 30, 60, 20, 50, 40, 10 } 走完第一轮外层循环（startIndex = 0）后，数组是什么？

迭代器（iterators）：统一遍历的接口

📐 概念：iterator 与 one-past-the-end

官方定义：迭代器是一个设计用来遍历容器（数组元素、字符串字符……）并在途中提供每个元素访问的对象。C++ 迭代器用统一接口：operator++ 移到下一元素、operator* 访问当前元素。指针就是最简单的迭代器（17.2 课指针算术的续集）：

std::array arr{ 0, 1, 2, 3, 4, 5, 6 };

auto begin{ &arr[0] };
auto end{ begin + std::size(arr) };  // one-past-the-end：最后一个元素
                                     // '再来一个'会在的位置——永不解引用！

for (auto ptr{ begin }; ptr != end; ++ptr)
    std::cout << *ptr << ' ';
  • 遍历所需的最小集合：begin 点、end 点、operator++、operator*；
  • 迭代器循环条件惯用 != 而非 <——有些迭代器类型不支持关系比较，但 != 对所有迭代器都可用；
  • 所有标准库容器提供 begin()/end() 成员；<iterator> 还有泛型 std::begin/std::end（C-style 数组也能用）；
  • range-based for 的底层就是它们：任何"有 begin()/end() 成员或可用于 std::begin/std::end"的类型都能用于 range-for（decayed 的 C 风格数组不行——类型里没长度信息）；
  • ⚠️ 求 end 别写 &arr[std::size(arr)]——那会解引用越界元素（UB）；用 begin + std::size(arr) 或 arr.data() + std::size(arr)。

判断③ "end 迭代器指向的是'最后一个元素再往后一个位置'，永远不应该解引用它。"

迭代器失效（iterator invalidation）

⚠️ 容器一变，迭代器作废

迭代器内部依赖"元素在哪儿"。元素换地址或被销毁时，既有迭代器悬空（dangling），继续使用是 UB——这正是 16 章 vector 重分配知识的直接后果：

// 反例：遍历中 push_back → 可能重分配 → 全部迭代器失效（UB）
for (auto num : v)
    if (num % 2 == 0)
        v.push_back(num + 1);

// 反例：erase 之后继续用旧迭代器（UB）
auto it{ v.begin() };
++it;
v.erase(it);
++it;   // ❌ it 已失效

// 正解（对比上面：这次接住 erase() 的返回值，而不是继续用旧 it）
it = v.erase(it);   // ✅ it 现在指向原第二个元素之后的元素

好的文档（如 cppreference 的 std::vector "Iterator invalidation" 小节）会列出哪些操作会失效哪些迭代器——改容器的操作后，要么重新拿迭代器，要么用返回值。

预测⑤ std::vector v{1,2,3,4,5,6,7};，auto it{ v.begin() }; ++it; 后执行 it = v.erase(it);。之后 *it 是多少？

💭 思维转变：循环变量从"下标"变成"位置标记"

17.2 课你已经用 begin/end 遍历过数组；本课把它升格为通用思想：迭代器把"位置"从"数据"里抽象出来——下标是"第几个"，迭代器是"在哪儿、怎么到下一个"。这就是为什么 std::list（链表）没有下标却有迭代器。下一课：标准库拿这个统一接口造了一整柜子现成算法。
