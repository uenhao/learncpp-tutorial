18.2 标准库算法与计时：别手写了，库里有

上一课你手写了选择排序——现在把它扔进历史的垃圾桶。标准库算法预测试、高效、跨容器、可并行；本课示范最常用的几个，再用 <chrono> 计时器量化"标准库 vs 手写"的差距。（原文 18.3–18.4）

算法库速览

📐 概念：迭代器区间 [begin, end) 与常用算法

算法都在 <algorithm>（std::greater 在 <functional>），统一接受 [begin, end) 迭代器区间（end 是 one-past-the-end）。三大类：检查者（只读：搜索、计数）、变更者（修改：排序、洗牌）、辅助者（生成结果：比较对象等）。

std::array arr{ 13, 90, 99, 5, 40, 80 };

// find：返回首个匹配的迭代器；找不到返回 end()！
auto found{ std::find(arr.begin(), arr.end(), 99) };
if (found == arr.end())
    std::cout << "Could not find\n";
else
    *found = 42;   // 迭代器可读写元素

// find_if：第一个满足谓词（callable）的元素
auto nut{ std::find_if(words.begin(), words.end(), containsNut) };

// count_if：统计满足谓词的个数
auto nuts{ std::count_if(words.begin(), words.end(), containsNut) };

// sort：默认升序（按 operator<）；传比较函数自定义
std::sort(arr.begin(), arr.end(), greater);  // 降序

// for_each：对每个元素施加同一函数
std::for_each(arr.begin(), arr.end(), doubleNumber);
  • 谓词/比较都是可调用对象：函数名（不带括号的函数指针）或 lambda（20 章）；
  • 比较函数语义："第一个参数应排在第二个参数之前"时返回 true；
  • 降序常用 std::sort(arr.begin(), arr.end(), std::greater{});——必须加大括号：greater 是类型不是函数，{} 实例化一个对象；
  • C++20 的 ranges 版不必再传区间：std::ranges::for_each(arr, doubleNumber);。

判断① "std::find 找不到目标时返回 end() 迭代器——所以判'找到没有'就是拿结果和 end() 比。"

选择② std::sort(arr.begin(), arr.end(), std::greater{}); 里的 {} 为什么必须写？

📐 概念：for_each 相比 range-based for 的优势
void doubleNumber(int& i) { i *= 2; }

std::for_each(arr.begin(), arr.end(), doubleNumber);   // ✅ 推荐

for (auto i : arr)          // ❌ 忘写 &：改的是拷贝！
    doubleNumber(i);
for (auto& i : arr)         // ✅ 但全靠手写对
    doubleNumber(i);
  • 意图清晰：一看到 for_each 就知道"对每个元素做同一件事"；
  • 防三类手误：忘写 &（改拷贝不生效）、元素类型隐式转换、把错误变量传进函数——for_each 都不可能发生；
  • 能跳元素：std::for_each(std::next(arr.begin()), arr.end(), f); 跳过首元素（range-for 做不到）；
  • 可并行化：标准库算法多支持并行执行；
  • ⚠️ 顺序保证：std::for_each 保证逐个按前向顺序访问；多数算法只有性能保证——依赖"第 i 个乘 i"这种顺序逻辑时，只用有顺序保证的算法（for_each / copy / move 等）。

判断③ "能用标准库算法就别手写同功能代码——但用之前要确认它的性能与执行顺序保证符合你的场景。"

计时你的代码（<chrono>）

📐 概念：Timer 类（steady_clock）

<chrono> 的用法有点绕，但可以全部封装进一个小类（本站 14–17 章的类知识正好用上——构造函数记录起点、成员函数算经过）：

class Timer
{
private:
    using Clock = std::chrono::steady_clock;
    using Second = std::chrono::duration<double, std::ratio<1>>; // 秒（double）

    std::chrono::time_point<Clock> m_beg{ Clock::now() }; // 构造即起表

public:
    void reset() { m_beg = Clock::now(); }

    double elapsed() const
    {
        return std::chrono::duration_cast<Second>(Clock::now() - m_beg).count();
    }
};

Timer t;
sortArray(array);   // 要计时的代码
std::cout << t.elapsed() << " seconds\n";
⚠️ 计时方法论（原文要点）
  • 用 release 构建测：debug 关优化影响巨大——官方同一代码 debug 慢 33 倍；
  • 至少测 3 次：结果相似才可信；方差大 = 有干扰（后台 CPU 任务、杀毒扫描、"无辜的"空闲浏览器都能把 CPU 打满）；
  • 别把等待用户输入计进去；随机数序列也影响计时——固定 seed 可复现，但也可能误导；
  • 绝对时间不可跨机器比较；单机上的相对比较才有意义（版本 A 10s vs 版本 B 8s）；
  • Sanity check：测完变体 B 后重测变体 A，结果对得上才可比。

选择④ 要给代码计时，应该用哪种构建？

判断⑤ "在你的机器上测出代码 A 花 10 秒，就能断定它在任何机器上都比花 8 秒的 B 慢 25%。"
