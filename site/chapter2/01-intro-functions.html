2.1 函数：把语句打包复用

其实你从第一行代码起就在用函数了——main 就是函数，只不过它是被操作系统调用的。这一课正式揭开"函数是什么"，以及程序执行时到底发生了什么。

📐 概念

函数（function）：被命名的语句集合，可以反复"调用（call）"。

函数调用：CPU 跳去执行函数体，执行完毕后回到调用处继续。

语法结构：返回类型 函数名(参数列表) { 语句... }——本课先用最简单的 void（无返回值、无参数）。

#include <iostream>

void doPrint()              // 定义：一个名为 doPrint 的函数
{
    std::cout << "In doPrint()\n";
}

int main()
{
    std::cout << "Starting main\n";
    doPrint();              // 调用：执行权跳到 doPrint
    std::cout << "Ending main\n";
    return 0;
}

调用是怎么"回来"的？

执行模型的升级版：CPU 现在不只是向下走，还会"跳出去再跳回来"。跟踪一遍上面的程序，注意每一步"执行权"在谁手里：

main 开头
doPrint() 体内
回到 main 的下一句
main 结束

逐步拆开：

  1. main 开头——执行 std::cout << "Starting main\n"，屏幕出现第一行；紧接着遇到 doPrint();。
  2. doPrint() 体内——执行权整个跳走：main 被"冻结"在调用这一行，CPU 去执行 doPrint 的函数体，打印 In doPrint()。函数体执行到右花括号，标志着 doPrint 的工作结束。
  3. 回到 main 的下一句——执行权带着"doPrint 干完了"的消息返回 main，从调用处的下一条语句继续：打印 Ending main。注意不是回到 main 开头重来，而是精确接在离开的地方。
  4. main 结束——执行 return 0;，把"程序成功"的状态码交回操作系统，程序生命周期终结。

每个函数执行完，都自动回到它被调用的那一行的下一条语句。函数可以嵌套调用（A 调 B，B 调 C），执行权像传接力棒，每一棒结束时都还给上一棒。

🎯 预测输出（一行内，空格分隔）：

void a() { std::cout << "A start "; c(); std::cout << "A end "; }
void b() { std::cout << "B "; }
void c() { std::cout << "C "; }

int main() { a(); b(); }
⚠️ 一个你现在就会踩的坑：先用后定义

上面预测题的代码其实编译不过——a() 里调用了 c()，但 c 定义在 a 的后面。编译器自上而下工作，读到 a 的函数体时还不知道 c 存在。解法（前向声明）是 2.4 课的主角；现在先记住现象：编译器不预读整个文件。

判断"main 也是函数，所以可以在自己的代码里调用 main() 来让程序重新开始。"

💭 思维转变：函数是"动词"的封装

写 main 之前的思维是"我要做 A 然后 B 然后 C"；有了函数，思维升级为"这件事可以命名，命名后可以谈论、复用、替换"。doPrint() 三个字读起来就是一句英文命令——好的函数名让代码读起来像描述意图，而非罗列步骤。第 2.3 课会专门训练"什么时候该抽函数"。
