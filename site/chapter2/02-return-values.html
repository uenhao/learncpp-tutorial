2.2 返回值与参数：函数的输入与输出

上一课的函数像"只会说话的盒子"。真正的函数是有进有出的：数据从参数进来，结果从返回值出去。

📐 概念

形参（parameter）：定义函数时括号里的名字，如 int add(int x, int y) 的 x、y。它们是函数体内的局部变量。

实参（argument）：调用时括号里的值，如 add(3, 4) 的 3、4。

按值传递（pass by value）：调用时实参的值被拷贝给形参。从此形参自成一个独立对象。

返回值（return value）：return 表达式; 把一个值交回调用处，函数立即结束。

int add(int x, int y)     // x、y：形参（局部变量）
{
    return x + y;         // 计算结果交回去，函数结束
}

int main()
{
    int sum{ add(3, 4) }; // 3、4：实参；返回值 7 初始化 sum
    std::cout << sum;
}

调用那一刻发生了什么？

把 add(3, 4) 这一行执行时发生的事逐步展开，你脑中的世界应该是这样：

实参 3 拷贝给 x
实参 4 拷贝给 y
执行函数体
return 把 7 送回调用处
x、y 销毁

逐步拆开：

  1. 实参 3 拷贝给 x——调用发生，先"布置场地"：创建形参 x（add 的局部变量），把实参的值 3 拷贝进去。此时 add 的世界里有了 x = 3。
  2. 实参 4 拷贝给 y——同样地，第二个形参 y 被创建并拷入 4。参数按位置一一对应：第 1 个实参给第 1 个形参，第 2 个给第 2 个。
  3. 执行函数体——CPU 跳到 add 内部，计算 x + y，即 3 + 4 = 7。main 仍然"冻结"在调用行等待。
  4. return 把 7 送回调用处——return x + y; 做两件事：把 7 这个值交给 main（在那里它用于初始化 sum），同时立即结束 add 的执行。
  5. x、y 销毁——add 的"世界"被拆除：形参 x、y 是局部变量，随函数结束而消失。它们带走的任何修改（如果有）也随之蒸发——这就是"按值传递"的完整含义。

注意最后一格：形参随函数结束而销毁（局部作用域，1.2 课的规则）。这就是"函数是独立世界"的含义——它每次调用都领到全新的拷贝，也带走一切内部状态。

选择运行下面代码后，a 的值是多少？

void setTo100(int x)
{
    x = 100;
}

int main()
{
    int a{ 5 };
    setTo100(a);
    std::cout << a;
}

返回值的规矩

⚠️ 反例：有返回类型的函数"漏了出口"
int score(int s)
{
    if (s >= 60)
        return 1;
    // s < 60 时走不到任何 return！
}

编译器会警告 control reaches end of non-void function。这不是风格问题——函数结束时没有值可交回，是未定义行为。规则：每个执行路径都必须 return。修法很简单：在末尾补 return 0;。

返回值的三种用法：

int sum{ add(2, 3) };         // ① 接住：初始化变量
std::cout << add(2, 3);       // ② 直接用：送进输出流
add(1, 2);                    // ③ 丢弃：合法但几乎总是写错了

判断"void 函数里写 return;（不带值）是语法错误。"

💭 思维转变：函数 = 契约

函数头 int add(int, int) 是一份契约："给我两个 int，我还你一个 int"。调用者只需要信契约，不需要读实现（第 0 章链接器的分工正是基于此）；实现者只需要守契约，可以随时重写实现。这种"接口与实现分离"的思维，是从小脚本走向大工程的分水岭——第 2.6 课的头文件就是契约的物理载体。

🎯 预测输出（三段，空格分隔）：

void modify(int x) { x = 100; std::cout << x << ' '; }

int main()
{
    int a{ 5 };
    std::cout << a << ' ';
    modify(a);
    std::cout << a;
}
