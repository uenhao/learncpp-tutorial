2.3 局部作用域与重构时机

1.2 课你见过块作用域。函数把作用域规则推向了一个重要结论——每个函数是一个独立的变量世界。本课先夯实这个模型，再回答一个实用问题：什么时候把代码抽成函数？

每个调用都是全新的世界

void counter()
{
    int calls{ 1 };   // 每次调用都重新创建！
    ++calls;
    std::cout << calls << '\n';
}

int main()
{
    counter();   // 2
    counter();   // 2  ← 不是 3！
    counter();   // 2  ← 不是 4！
}

三次调用打印三个 2。因为 calls 是局部变量：进入函数时诞生，离开时销毁，对上次调用毫无记忆。"让函数记住东西"需要 static 或别的手段——先按下不表，记住现象即可。

选择两个不同的函数各自定义了 int count{ 0 };，会冲突吗？

什么时候该抽出一个函数？

看这段真实代码：

int main()
{
    // ... 订单 1
    int tax1{ 1000 * 8 / 100 };
    int total1{ 1000 + tax1 };
    std::cout << total1 << '\n';
    // ... 订单 2（同样三行，数字不同）
    int tax2{ 250 * 8 / 100 };
    int total2{ 250 + tax2 };
    std::cout << total2 << '\n';
    // ... 订单 3、4、5……
}

同样的"算税 + 加总 + 输出"复制了 N 遍。判断"该不该抽函数"，learncpp 给了三个信号：

📐 抽函数的三个信号
  1. 重复：同一段逻辑出现两次以上
  2. 可命名：这段逻辑能用一个动词短语概括（printWithTax）
  3. 输入输出清晰：需要什么数据、产出什么结果说得清楚
int withTax(int cents)              // 输入：税前价
{
    return cents + cents * 8 / 100; // 输出：税后价
}

int main()
{
    std::cout << withTax(1000) << '\n';
    std::cout << withTax(250)  << '\n';   // 需求变更？只改一处！
}
✅ 重构的复利

现在需求改成"税率 8% 变 10%，且满 500 打九折"——改一个函数，全程序生效。没重构的版本要改 2N 行。这就是"消除重复"的复利：代码不是写完就完，是要被改的。

选择以下哪种情况最不需要抽函数？

💭 思维转变：写代码 = 三次创作

第一次让它能跑；第二次让它能读（重命名、抽函数）；第三次让它能改（消除重复、隔离变化）。初学者止步于第一次。learncpp 的建议：写完一个能跑的版本后，回头花 10 分钟做第二、三次——这段投资在你下次改需求时连本带利地还给你。

🎯 预测输出（三段，空格分隔）：

void counter()
{
    int calls{ 1 };
    ++calls;
    std::cout << calls << ' ';
}
int main() { counter(); counter(); counter(); }
