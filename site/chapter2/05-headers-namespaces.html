2.5 头文件与命名空间：代码的组织学

2.4 课的结尾留了动机："声明应该只写一次、处处引用"。本课给出 C++ 的标准答案——头文件，以及解决名字打架问题的命名空间。

头文件：声明集中营

📐 概念：三件套结构
文件放什么
math_utils.h函数声明（契约清单）
math_utils.cpp函数定义（兑现）
main.cpp 等消费者#include "math_utils.h" 然后直接调用

#include 的本质（0.1 课说过）：预处理器把头文件内容原样粘贴到 include 处。于是"写一次声明"变成"写一次，粘贴到每个需要它的文件"。

// math_utils.h
#ifndef MATH_UTILS_H        // 头文件保护：2.6 课的主角
#define MATH_UTILS_H

int square(int x);
int cube(int x);

#endif
// math_utils.cpp
#include "math_utils.h"     // ★ 先 include 自己的头！

int square(int x) { return x * x; }
int cube(int x) { return x * x * x; }

那个 ★ 是重要的职业习惯：源文件先 include 自己的头文件。这样如果声明和定义不一致（比如改了 .h 忘了改 .cpp 的签名），编译器在编译这个 .cpp 时当场报错，而不是等到别的文件链接时给出一条模糊的错误。

命名空间：给名字划定管辖区

两个第三方库都提供 doSomething() 怎么办？命名空间（namespace）把名字圈进各自的领地，用 ::（作用域解析运算符）指名道姓：

namespace alexmath
{
    int doSomething(int x, int y) { return x + y; }
}

namespace bobmath
{
    int doSomething(int x, int y) { return x - y; }
}

int main()
{
    alexmath::doSomething(4, 3);   // 7
    bobmath::doSomething(4, 3);    // 1
}

你其实早就在用它：std::cout 的 std 就是标准库的命名空间——正因成千上万个标准名字都住在 std 里，你才能放心定义自己的 count、swap 而不相撞。

using：便捷与风险的交易

using std::cout;         // 只引入一个名字：风险小，可接受
using namespace std;     // 倾倒整个 std：方便，但危险！
⚠️ 为什么 learncpp 反对 using namespace std

std 里有几千个名字，其中 count、swap、data、size 都极易与你自己的变量撞车。撞车后报错信息往往晦涩难懂。头文件里写 using namespace 危害加倍——它会强制污染所有 include 它的文件，而那个文件的作者可能毫不知情。习惯：cpp 文件里可用 using std::cout; 这类单名引入；头文件里两者都别用。

判断"在头文件里写 using namespace std; 只影响这个头文件自己。"

💭 思维转变：物理组织反映逻辑组织

.h/.cpp 拆分不只是"文件多了好找"。它在回答一个结构性问题：哪些是"别人需要知道的"（接口 → .h），哪些是"内部怎么做到的"（实现 → .cpp）。命名空间则在回答"这些名字归谁管"。文件结构、名字结构和你脑子里的概念结构对齐了，代码库才可能长大——这就是"组织学"的含义。
