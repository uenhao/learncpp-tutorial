3.1 语法错误与语义错误

软件错误遍地都是——犯错误很容易，找错误却很难。本章专门讲"如何找到并消灭 bug"，包括如何使用 IDE 里的集成调试器。调试工具虽然不属于 C++ 标准，但找 bug 的能力决定了你能不能成为合格的程序员：程序越写越复杂，诊断问题的能力必须同步升级。

好消息是：错误虽然五花八门，但基本都落在两大类里。先把分类搞清楚，遇到 bug 才知道该用什么武器。

语法错误（syntax errors）

📐 概念

语法错误：写出的语句不符合 C++ 语言的语法规则。漏分号、括号不配对、花括号不配对，都属于这一类。

关键性质：语法错误百分之百会被编译器当场抓住——编译器就是语法的执法者。

一个"集大成"的语法错误示例（原文同款）：

#include <iostream>

int main( // 错 1：缺右括号
{
    int 1x; // 错 2：变量名不能以数字开头
    std::cout << "Hi there"; << x +++ << '\n'; // 错 3：多余的分号；错 4：operator+++ 不存在
    return 0 // 错 5：语句末尾缺分号
}

处理语法错误的流程简单到不需要思考：编译 → 读第一条报错 → 修复 → 再编译，循环直到零错误。你在第 0 章已经练过了。

语义错误（semantic errors）

📐 概念

语义错误：语句在语法上完全合法，但含义错了——要么违反了语言的其他规则，要么没做程序员想让它做的事。

这是本章的主角，因为它不会都被编译器抓住。

语义错误按"谁抓得住"分三个层级：

层级 1：编译期能抓的语义错误

int main()
{
    5 = x;           // x 未声明；而且不能给字面量 5 赋值
    return "hello";  // 字符串没法转成 int 返回
}

类型不匹配、使用未声明的名字——编译器照样拦下你。这类错误虽然"语义"错了，但待遇和语法错误一样：读报错、修复、重编译。

层级 2：运行时崩溃的语义错误

#include <iostream>

int main()
{
    int a { 10 };
    int b { 0 };
    std::cout << a << " / " << b << " = " << a / b << '\n'; // 除以 0！
    return 0;
}

程序能编译、能运行，然后当场崩溃。崩溃至少是个响亮的信号——它告诉你"这里有 bug"，虽然不告诉你在哪。

层级 3：不崩溃、只给出错误结果的语义错误（最危险）

int add(int x, int y) // 这个函数本该做加法
{
    return x - y;     // 却写成了减法
}

int main()
{
    std::cout << "5 + 3 = " << add(5, 3) << '\n'; // 应输出 8，实际输出 2
    return 0;
}

再比如 return 之后还有语句（永远执行不到）、读取未初始化的变量……这类错误不喊不叫：程序平静地给出错误答案，你可能过了三天才发现。在小程序里靠肉眼还能看出来；在真实项目里，靠盯着代码看是找不全的——这正是本章后面要教调试技术的理由。

分类以下四个问题，哪个属于"运行时语义错误"？

💭 思维转变：错误分三个"层级"，武器各不相同

编译期错误（语法 + 部分语义）→ 读报错就够了；链接期错误 → 检查名字与文件清单（0.1 课）；运行时语义错误 → 编译器帮不了你，需要本章剩下的全部内容：调试流程、定位策略、调试器。把"bug 属于哪一层"判断清楚，是高效解决 bug 的第一步——最怕的就是拿着"读报错"的武器去对付一个不报错的运行时 bug。

🎯 预测输出（整行，含前缀）：

int add(int x, int y)
{
    return x - y;   // 手滑
}
int main()
{
    std::cout << "5 + 3 = " << add(5, 3) << '\n';
}
