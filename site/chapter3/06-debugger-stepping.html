3.6 调试器：单步执行

📐 概念：调试器（debugger）与集成调试器

调试器：让你控制程序"怎么执行"（跑多快、停在哪儿）并在运行中检查程序状态的工具。集成调试器：直接嵌在编辑器/IDE 里的调试器——VS Code 的调试功能就是一个。

调试器能做的事，打印法全都要改代码才能做；而调试器零代码侵入。这是本章后四课的主角。

⚠️ 前提：必须是 Debug 构建！

0.2 课埋的伏笔在这里兑现：调试必须在 Debug 构建下进行。Release 的优化会把变量塞进寄存器、重排语句、内联函数——调试器的"停在源码第 N 行、查看变量"将失去依据。如果你调试时发现变量全是 < optimized out>、断点不命中，第一反应应该是检查构建配置。

对照实验：打印法 vs 调试器

还是 3.4 课那个 return --x; 的 bug。打印法的流程是：改代码（加 cerr）→ 编译 → 运行 → 读输出 → 再改代码（换位置）→ 再编译 → ……每一轮观察都要付出"改代码 + 重编译"的成本。

用调试器：一次编译 → F5 启动 → 单步走、随时看变量、想看哪看哪——观察是免费的，且不修改代码。3.4 课批评的四个缺点（弄脏代码/输出、引入新 bug、不可复用）全部消失。

核心命令：单步执行的三个变体

📐 概念：Step into / Step over / Step out

这三个命令都执行"当前语句"，区别在遇到函数调用时往哪走：

命令遇到函数调用时什么时候用
Step into（逐语句）钻进函数体，停在函数第一行怀疑 bug 在这个函数内部
Step over（逐过程）把整个函数执行完，停在下一行相信这个函数没问题，不想进去浪费时间
Step out（跳出）执行完当前函数剩余的全部代码，停在返回处不小心 step into 了不感兴趣的函数，想出来

三个命令都把程序停在"下一条语句"，然后把控制权交给你。

VS Code 中的操作（本项目配置）

本项目根目录的 .vscode/launch.json 已配好调试。步骤：

  1. 打开任意 .cpp（先用 chapter3/06-debugger-stepping/ 的 stepping_demo.cpp）
  2. 确认底部状态栏构建变体是 CMake: [Debug]，按 F7 构建
  3. 按 F5 启动调试——程序停在 main 入口，当前行高亮（执行标记）
命令VS Code 快捷键/按钮行为
Step overF10（顶部工具栏 →⃠ 图标）执行当前行；若是函数调用，整个函数跑完
Step intoF11（↓ 图标）执行当前行；若是函数调用，钻进函数第一行
Step outShift+F11（↑ 图标）执行完当前函数剩余部分，停在调用处的下一行

原文的演示程序：

#include <iostream>

void printValue(int value)
{
    std::cout << value << '\n';
}

int main()
{
    printValue(5);   // 停在这里时：
    return 0;        //   F10 → 直接打印 5 并跳到下一行
                     //   F11 → 钻进 printValue 的第一行
}

动手实验（本章第一个真正的调试器练习）：

  1. F5 启动，停在 printValue(5);；
  2. 按 F11（step into）→ 你进入了 printValue 的函数体，高亮在 std::cout 行；
  3. 按 Shift+F11（step out）→ 函数执行完毕（屏幕出现 5），你回到 main 的下一行；
  4. 再来一次，这次按 F10（step over）→ 没有钻进去，直接打印 5 并跳到下一行。

感受一下区别了吗？step into 是"进去查"，step over 是"跳过去"，step out 是"查完出来"。三者配合：怀疑谁就 into 谁，查完就 out 出来，信任的就 over 过去。

⚠️ Step into 钻进"不速之客"怎么办

对 std::cout << x 这类标准库语句按 F11，可能钻进一屏幕你看不懂的模板代码。补救：连续按 Shift+F11（step out）跳出来，改用 F10 重走。经验法则：标准库调用、assert 等一律 F10；只对自己写的、有嫌疑的函数用 F11。

选择你停在 int result{ calculateScore(userInput) }; 这一行，怀疑 calculateScore 有 bug。应该用哪个命令？

💭 思维转变：从"改代码观察"到"免修改观察"

本章前五课的所有战术都要"修改代码才能收集信息"；调试器的单步执行第一次做到了观察零侵入。别小看这个差别：加打印要重编译（大项目要几十分钟）、要记得删、还可能改错；而单步执行想看哪停哪、想看多少遍看多少遍。原文反复强调：调试器的学习成本会在省下的调试时间上百倍赚回。接下来两课给它加上两个放大器：断点（不必逐行走）和变量监视（不必逐个打印）。
