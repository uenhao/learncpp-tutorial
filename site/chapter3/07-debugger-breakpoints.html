3.7 调试器：断点与运行控制

单步执行的痛点：大程序里，从 main 走到你想看的那一行要按几十次 F10。这一课的命令让你直接跳到想看的地方。

Run to cursor（运行到光标）

📐 概念

Run to cursor：程序一直运行，直到执行到光标所在的语句，然后停下交还控制权。相当于"瞬移到这一行开始调试"。

VS Code 操作：调试进行中，在目标语句上右键 → Run to Cursor。

演示程序（原文同款）：

#include <iostream>

void printValue(int value)
{
    std::cout << value << '\n';
}

int main()
{
    printValue(5);
    return 0;
}

启动调试（F5）后，右键第 5 行 → Run to Cursor：程序瞬间跑到这一行停下。从这一行开始单步、看变量，都随你。注意：如果光标所在的行永远不会被执行（比如 return 之后的死代码），程序会一路跑到底。

Continue 与 Start

命令VS Code做什么
Continue（继续）F5（调试中）从当前位置正常跑下去，直到程序结束或撞上断点才停
Start（启动调试）F5（未调试时）从头开始一个调试会话

同一个 F5 键，语境不同含义不同：未调试时是 Start，调试暂停中是 Continue。

断点（breakpoint）——本章最重要的工具

📐 概念

断点：打在某行代码上的特殊标记。调试模式下程序每次即将执行到这一行都会停下，把控制权交给你。

VS Code 操作：行号左侧的灰色区域点击一下（出现红点），或光标放行内按 F9，或右键 → Toggle Breakpoint。再点一次红点即取消。

#include <iostream>

void printValue(int value)
{
    std::cout << value << '\n';   // ← 在这行打个断点
}

int main()
{
    printValue(5);
    printValue(6);
    printValue(7);
    return 0;
}

打上断点，按 F5 启动：程序不跑到底，而是停在 std::cout 那行。此时按 Continue：打印 5，程序继续跑——然后又停下了！因为 printValue(6) 也要执行这一行。再 Continue，第三次停。再 Continue，程序跑完。

📐 断点 vs Run to cursor：一字之差，天壤之别
  • Run to cursor：一次性命令——只停第一次；
  • 断点：持久标记——每次经过都停，且一直保留到你手动删除。

循环体、被多次调用的函数入口，用断点；单次跳跃，用 run to cursor。两者都不触发的情况：断点所在的行根本不在执行路径上（比如死代码）。

Set next statement（跳转执行点）

📐 概念（低频但值得知道）

Set next statement（跳到语句）：调试暂停时，把"下一条要执行的语句"改成你指定的行——可以向后跳（跳过某些代码不执行），也可以向前跳（让已执行过的代码再跑一遍）。VS Code 操作：调试中右键目标行 → Jump to Cursor。

向后跳的实验：停在 printValue(5);（已打印 5），右键 printValue(7); → Jump to Cursor → Continue。输出是 5 和 7——printValue(6) 被整个跳过了。这相当于"运行时版的注释掉代码"（3.4 战术一），但不改代码。向前跳则让刚看过的函数再跑一遍，方便配合监视窗口反复观察。

⚠️ 两条原文警告
  • 跳转只改变执行位置，不改变程序状态——变量保持着跳转前的值。向前跳"重跑"时变量可能带着"未来"的值，行为可能和自然执行完全不同。慎用，尤其向前跳。
  • 绝不要把执行点跳到另一个函数里——调用栈会被破坏，多半直接崩溃（未定义行为）。

选择循环体 for (int i{0}; i < 100; ++i) { process(i); } 里 process 偶尔出错。你怀疑第 37 次调用附近有问题。最省力的调试器用法是？

💭 思维转变：断点是"程序里的观察哨"

把断点想成你在程序地图上布下的观察哨：布好后按一次 F5，程序自己跑，每到一处哨点自动"叫停汇报"。相比 run to cursor（每次手动指路），断点让你从"驾驶员"变成"调度员"—— especially 在多次调用、循环这类重复路径上。加上前两课的工具，你的定位工具箱已经完整：hi-lo 策略决定在哪布哨（3.3），断点+单步负责现场勘查（3.6/3.7）。还差最后一块拼图——不挪步也能看清现场细节的"望远镜"：变量监视（3.8）。
