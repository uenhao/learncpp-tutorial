3.8 调试器：监视变量

前两课你学会了"控制程序怎么走"。这一课补上另一半：随时查看变量的值——不打印、不改代码。

观察变量 x 的三种姿势

演示程序：

#include <iostream>

int main()
{
	int x{ 1 };
	std::cout << x << ' ';

	x = x + 2;
	std::cout << x << ' ';

	x = x + 3;
	std::cout << x << ' ';

	return 0;
}

程序打印 1 3 6。启动调试（F5），用 Run to Cursor 停在第 6 行（std::cout << x << ' '）——此刻 x 已创建并初始化为 1。

姿势一：悬停（hover）

调试暂停时，把鼠标悬停在变量名上——VS Code 会弹出小窗显示当前值。对程序里任何位置的 x 悬停都有效（不只当前行）。看一眼就走，最快。

姿势二：Watch 窗口（监视窗口）

📐 概念

监视窗口（watch window）：把你关心的变量登记进去，调试过程中它的值实时更新——单步一次、自动刷新一次。悬停是"问一次答一次"，监视是"全程跟踪"。

VS Code 操作：调试暂停时，左侧边栏出现"运行和调试"面板，其中 WATCH（监视）区域——点 + 输入变量名（或在代码里右键变量 → Add to Watch）。把 x 加进去，然后 F10 单步，看着它从 1 → 3 → 6 变化。

姿势三：Local 变量区（顺带福利）

调试面板里还有一个 VARIABLES / LOCAL（局部变量）区：当前函数的所有局部变量自动列出，不用登记、自动刷新。很多时候根本不需要手动加 watch——扫一眼 Local 区就够了。监视窗口留给"只在远处定义、Local 区看不到"的变量，以及"想持续盯一个表达式"的场景。

监视窗口的高级用法：看表达式

监视窗口不仅能放变量名，还能放表达式——它会按当前程序状态求值：

x            6      // 当前值
x + 10       16     // 表达式也能算
x * x        36

这相当于"随时可改的打印语句"——想看什么组合就在观察点算什么，依然零代码侵入。

⚠️ 监视的是"当前作用域"的变量

监视 x 后一路单步走出了 x 的作用域（或钻进了另一个没有 x 的函数），监视项会显示错误或空值——变量不在场。程序走回 x 可见的位置，监视项恢复显示。另外老规矩：必须在 Debug 构建下监视才有意义，Release 下变量可能已被优化掉。

三件套合体：一次完整的调试会话

用 3.4 课的 add(x, 5) bug 演示现代调试流程（对照打印法数一数省了多少步）：

  1. 在 int z{ add(x, 5) }; 打断点；
  2. F5 → 程序停在断点，Local 区自动显示 x、y（不用打印）；
  3. 发现 x=4、y=3 正常 → F11 step into add；
  4. Local 区显示形参 x=4、y=5——输入 y 是 3，进来变成 5！
  5. Step out 回到 main，盯着调用行看：实参写的是 5 不是 y。破案。

全程没改一行代码、没编译一次、没被输出刷屏。打印法要 3 轮"改代码-编译-运行"，这里一次会话搞定。

判断"监视窗口里加了变量 x，之后无论程序执行到哪里，监视项都会显示 x 的当前值。"

选择以下哪件事做不到？

💭 思维转变：程序状态从"黑盒"变成"透明鱼缸"

3.4 课的打印法本质是"隔玻璃看鱼"——你只能看到你提前布置的那几行 cerr 输出；调试器是把整个鱼缸换成透明玻璃：任意时刻、任意变量、任意表达式，随意观察。再回忆 3.3 课的 hi-lo 策略——它需要"做观察"来缩小包围圈，而观察的成本决定策略的可行性：打印法一轮观察要改代码+重编译，所以你只敢放少量观察点；调试器让观察近乎免费，你可以大胆地多看、随时看。工具降低观察成本，观察成本决定调试策略——这就是本章课程顺序背后的逻辑。
