3.9 调试器：调用栈

2.1 课你学过函数调用机制："CPU 跳过去执行函数，执行完回到调用处的下一句"。但有个问题被我们悄悄略过了：程序怎么知道"回到哪"？这一课揭开谜底，顺带收获调试器的最后一件武器。

📐 概念：调用栈（call stack）

调用栈：一份"从程序启动走到当前执行点，经过了哪些活跃函数"的清单。每调用一个函数，就把它的条目压到栈顶；函数返回时，它的条目从顶部弹出，控制权回到它下面那条条目记录的位置。

栈里每个条目还记录着返回地址：该函数执行完后要回到的下一行代码。

亲眼看调用栈

演示程序（原文同款）：

#include <iostream>

void a()
{
	std::cout << "a() called\n";   // ← 第 5 行
}

void b()
{
	std::cout << "b() called\n";   // ← 第 10 行
	a();
}

int main()
{
	a();
	b();
	return 0;
}

在第 5 行和第 10 行各打一个断点，F5 启动调试（先命中第 5 行）。VS Code 左侧调试面板的 CALL STACK（调用堆栈）区，从下往上是：

a()        第 5 行     ← 栈顶：正在执行
main()     第 17 行    ← main 的下一行（返回地址）

解读：main 先被（操作系统）调用压栈；main 调用 a，a 压到顶。第 5 行是 a 里下一条要执行的语句；第 17 行是 a 返回后 main 里接着执行的语句。

📐 读栈规则

从下往上读 = 调用顺序（main → a）。栈顶是当前正在执行的函数；其余条目都是"正在等待返回"的函数。每条的行号含义：栈顶条目的行号 = 下一条要执行的语句；其余条目的行号 = 函数返回后将要执行的语句。

按 Continue 跳到第 10 行的断点（进入函数 b）：调用栈变成 b() → main()——a 已经返回，从栈里弹出了。再 Continue，命中第 5 行断点（b 调用了 a）：栈是三层 a() → b() → main()。整个调用历史一目了然。

调用栈在调试中的用法

📐 什么时候看调用栈

断点命中、而你想知道"我是怎么走到这里的"的时候。典型场景：某个底层函数（比如校验函数、错误处理函数）被很多地方调用——断点停在它里面时，看调用栈立刻知道这次是哪个调用者把它叫起来的。

另一大用途：程序崩溃时，崩溃瞬间的调用栈（栈顶=崩溃点，往下是调用链）直接告诉你"从哪条路径走到崩溃点的"——这是事后调试的第一线索。VS Code 里调试崩溃的程序，CALL STACK 区会自动展示这条链。

与 2.1 课的呼应：栈、作用域、生命周期

2.5 课说"局部变量随函数结束销毁"；2.2 课说"形参是按值拷贝的局部变量"。现在你有了完整的机制图景：每次函数调用压栈时，连同它的形参和局部变量一起"登记入住"；返回弹栈时整层销毁。

  • 2.5 课的 counter() 每次调用打印同样的值——因为每次压栈都是全新的一层，弹栈即清空，下层毫无记忆；
  • 3.8 课的"走出作用域监视项失效"——因为那一层栈已经弹掉了，变量不复存在；
  • 调用栈溢出（stack overflow，栈空间用尽）——通常是无休止的递归压栈。

选择程序执行到某断点时，调用栈显示（从顶到底）：c() → b() → a() → main()。谁调用了 c()？

判断"函数 a 返回后，调用栈上仍然保留着 a 的条目，以便下次调用 a 时查历史记录。"

💭 思维转变：机制串起来，知识才不散

这一课最有价值的不是"又一个调试窗口"，而是把散落各课的知识点焊成一个机制：函数调用（2.1）→ 形参拷贝与销毁（2.2/2.5）→ 局部变量生命周期（2.5）→ 调试器监视的作用域限制（3.8）→ 调用栈（3.9）。同一个"栈"机制解释了所有现象。学到后面你会遇到"栈溢出""递归""异常展开栈"——全都挂在这个机制上。当你能用一个机制解释五个现象时，才算真的学会了它。
