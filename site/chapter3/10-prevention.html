3.10 防患于未然

语义错误最阴险的地方：它可能潜伏很久才发作——某天新代码上线、或环境一变，它突然冒出来。潜伏越久，越难定位（调用它的代码越积越多、当初的上下文早就忘了）。所以最高明的调试是让错误少发生、发生了早发现。

第一道防线：少犯错

原文的清单，每一条都是实战经验：

  • 遵循最佳实践（本教程反复出现的"✅ 最佳实践"框就是干这个的）；
  • 累/烦躁时别写代码——休息，回来再写。疲惫时写的代码第二天自己都看不懂；
  • 熟悉语言的常见坑（教程里所有"⚠️ 反例"框警告的东西）；
  • 别让函数太长；
  • 能用标准库就不自己造轮子；
  • 注释充分；
  • 先做简单版本，再渐进加复杂度；
  • 拒绝炫技式写法；
  • 为可读性和可维护性优化，而不是性能。原文引用了 Brian Kernighan 的名言：
❝ 名言

"人人都知道，调试的难度是写程序的两倍。所以写程序时用尽聪明才智的人，将来要怎么调试它呢？" —— Brian Kernighan《The Elements of Programming Style》

重构（refactoring）：控制函数长度

📐 概念

重构：在不改变程序行为的前提下，调整代码的结构。目的：让程序更有条理、更模块化、更易读。

功能越加越多，函数不可避免变长——解法是把长函数拆成多个短函数（2.6 课的抽函数三个信号在这里全线适用）。多长算长？原文的标准：

  • 一屏放不下 = 太长（要滚动才能读完整，理解力骤降）；
  • 理想是 10 行以内，5 行以内更好；
  • 但目标是理解力，不是行数——牺牲清晰度硬凑行数是本末倒置。
✅ 关键铁律：行为改动与结构改动不同时做

改代码时，要么只改行为（加功能/修 bug），要么只改结构（重构），改完立刻重新测试。两者同时做，出了问题你分不清是新功能错了还是重构改坏了——错误更难找（等于给自己埋了 hi-lo 观察点都分辨不了的混合炸弹）。

第二道防线：快速发现

📐 概念：防御性编程（defensive programming）

程序员预先设想软件被误用的所有方式——用户输错、其他开发者（包括未来的你自己）用错——并提前检测、化解。例：提示用户输入整数，用户输入了字母怎么办？没防备的话程序会静默出错（1.4 课你亲手试过 "tom abc" 的提取失败）。

测试函数（unit testing 入门）

#include <iostream>

int add(int x, int y)
{
	return x + y;
}

void testadd()
{
	std::cout << "This function should print: 2 0 0 -2\n";
	std::cout << add(1, 1) << ' ';    // 期待 2
	std::cout << add(-1, 1) << ' ';  // 期待 0
	std::cout << add(1, -1) << ' ';  // 期待 0
	std::cout << add(-1, -1) << ' '; // 期待 -2
}

int main()
{
	testadd();
	return 0;
}

testadd() 用一组已知答案的输入"拷问" add：输出与期待一致 → add 基本可靠；不一致 → 立刻暴露。妙处是可以留下来——以后每次改动 add，重跑一次 testadd 就知道有没有改坏。这是单元测试的雏形：用小单元的自动化测试保证代码正确。（正规单元测试框架以后再学，思想一致。）

约束检查（constraints）

函数可以检查"我的假设是否被违反"。比如计算阶乘的函数理应收到非负数——收到负数时立即报错退出，而不是悄悄给出荒谬结果。assert 与 static_assert 是实现它的标准工具（第 9 章正式讲）。

静态分析（static analysis）

📐 概念

静态分析工具（俗称 linter）：不运行程序、只分析源码，找出常见语义问题的工具。

你已经有一个了——编译器！-Wall -Wextra 就是轻量静态分析：未初始化变量、类型窄化它都会警告。再往上有 cppcheck、clang-tidy 等专职工具，能查出几百类问题。原文最佳实践：给项目配一个静态分析工具（小程序可选，大项目强烈推荐）。

💭 思维转变：调试的最高境界是不调试

本章给你的其实是一条完整的"错误处理流水线"：预防（最佳实践/防御性编程）→ 快速发现（小步测试/断言/静态分析）→ 高效定位（hi-lo + 调试器）→ 有序修复（六步）→ 防回归（测试函数留下）。

注意箭头的经济性：越靠前的手段，单个错误的处理成本越低。一个被 -Wall 拦下的未初始化变量花你 10 秒；一个潜伏三个月才发作的它，可能花你一整天。所以"防患于未然"不是道德劝告，而是经济学：把成本投在最便宜的位置。从今天起，把"写完就测、测完就提交"当成呼吸一样的习惯。
