4.1 数据类型基础：比特、字节与 sizeof

1.2 课说"对象是一块能存值的内存"。这块内存到底长什么样？这一课下到最底层看一眼——然后你会明白为什么 C++ 需要"类型"这个东西。

比特与字节

📐 概念

比特（bit）：内存的最小单位，只能存 0 或 1（像电灯开关：关=0，开=1）。一段随机内存看起来就是 011010100101010…。

内存地址（address）：内存按顺序划分成的编号单元——像街道地址定位房子。

字节（byte）：作为一个整体操作的一组比特，现代标准是 1 字节 = 8 比特。关键事实：每个内存地址对应 1 个字节，而不是 1 个比特（地址数量有限，按比特编址太浪费）。

于是一个尴尬的问题出现了：假设你要存数字 65——它需要不止一个字节。内存只认识"一串比特"，它怎么知道这串比特是数字 65，而不是字符 'A'，也不是两个小数字？

📐 概念：数据类型（data type）——回答"这段比特是什么意思"

类型告诉编译器：如何解释这块内存的内容。声明 int x; 的含义是"这块内存按整数解释"。存入 65 时，编译器/CPU 把它编码成比特序列放进内存；读出时再按 int 规则还原成 65。类型就是比特 ↔ 值的翻译规则。

sizeof：一个类型/对象占几个字节

📐 概念：sizeof 运算符

sizeof(type) 或 sizeof(object)：返回该类型/对象占用的字节数。结果类型是 std::size_t（一种无符号整数，4.6 课细说）。它在编译期求值，零运行时开销。

#include <iostream>

int main()
{
    std::cout << "bool:\t"     << sizeof(bool)     << " bytes\n";
    std::cout << "short:\t"    << sizeof(short)    << " bytes\n";
    std::cout << "int:\t"      << sizeof(int)      << " bytes\n";
    std::cout << "long:\t"     << sizeof(long)     << " bytes\n";
    std::cout << "long long:\t" << sizeof(long long) << " bytes\n";
    std::cout << "float:\t"    << sizeof(float)    << " bytes\n";
    std::cout << "double:\t"   << sizeof(double)   << " bytes\n";
    std::cout << "char:\t"     << sizeof(char)     << " bytes\n";
    return 0;
}

典型输出（x86-64 Linux，g++）：

bool:   1 bytes
short:  2 bytes
int:    4 bytes
long:   8 bytes
long long: 8 bytes
float:  4 bytes
double: 8 bytes
char:   1 bytes
⚠️ C++ 只保证"最小尺寸"，不保证精确尺寸

标准只说 int 至少 16 位——具体多大由实现决定（现代 x86-64 上是 32 位，老系统可能是 16 位）。long 在 Windows 上是 4 字节、在 Linux 上是 8 字节。别把"我机器上 sizeof(int)==4"当成定律写进逻辑；需要精确宽度时用定宽整数（4.6 课）。这也是为什么查尺寸要用 sizeof 而不是背数字。

✅ sizeof(object) vs sizeof(type)

两者都合法：sizeof(int) 查类型；sizeof(x) 直接查对象（不必写 sizeof(int)）。对变量用后者更简洁。注意 sizeof 是运算符不是函数——对类型名才需要括号。

选择为什么内存按"字节"编址而不是按"比特"？

判断"内存里存着数字 65。读出时 CPU 能直接看出它是整数 65。"

💭 思维转变：类型 = 宽度 + 解释规则

学完这一课，你脑中的"类型"应该从"一种数据的名字"升级为"两个参数的组合"：占多少字节（决定能表示的范围）+ 比特如何解读（整数/浮点/字符）。后面 4.4–4.8 每学一种类型，都问这两个问题：多宽？怎么解释？——整章知识自动成表。
