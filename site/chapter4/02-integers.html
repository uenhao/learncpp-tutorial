4.2 整数类型与溢出

你从第一课就一直在用 int。现在把它讲透：C++ 其实有四种整数类型，它们各有溢出的脾气。

四种整数类型与有符号性

类型最小尺寸现代典型
short16 位16 位
int16 位32 位
long32 位Linux 64 位 / Windows 32 位
long long64 位64 位
📐 概念：符号（sign）

有符号（signed）整数：值的正负号本身编码在比特里，可正可负可为零。C++ 的整数默认就是有符号的——所以你写的 int 全名其实是 signed int。

无符号（unsigned）整数：只表示非负数（下一节细讲，以及为什么尽量别用）。

short s;        // 推荐短名，不写 short int
int i;
long l;         // 推荐 long，不写 long int
long long ll;   // 推荐 long long

signed int si;  // 合法但冗余——默认就有符号，别写 signed

有符号整数的范围

n 位有符号整数能表示 2^n 个值，范围是 −(2^(n−1)) 到 +(2^(n−1))−1（现代机器统一用"二进制补码"表示，C++20 已强制要求）：

宽度范围
8 位有符号−128 到 127
16 位有符号−32,768 到 32,767
32 位有符号−2,147,483,648 到 2,147,483,647
64 位有符号−9,223,372,036,854,775,808 到 9,223,372,036,854,775,807

选择8 位有符号整数的范围是 −128 到 127，而不是对称的 −127 到 127。多出来的"负一格"去哪了？

溢出（overflow）：越界的代价

⚠️ 有符号整数溢出 = 未定义行为

C++20 标准原话：表达式的结果"若在数学上无定义，或不在该类型的可表示范围内，则行为未定义"。把 140 塞进 8 位有符号整数？UB。

#include <iostream>

int main()
{
    // 假设 int 是 4 字节
    int x { 2'147'483'647 }; // int 的最大值（注意 ' 是 C++14 的数字分隔符，纯为可读）
    std::cout << x << '\n';

    x = x + 1; // 整数溢出 —— 未定义行为！
    std::cout << x << '\n';

    return 0;
}

原文作者的机器上输出：

2147483647
-2147483648

注意：这里"溢出后变成最小值"只是那台机器上 UB 的具体表现——补码回绕恰好如此。别把它当定律依赖：换编译器、开优化，UB 可以是任何行为（0.2 课 Debug/Release 崩溃差异的又一个来源）。

✅ 防溢出的两个习惯
  • 预判范围：乘法、累加是最容易溢出的运算。10 亿 × 10 早超 int；用 long long 或先想清楚数量级。
  • 别拿 UB 开玩笑：任何依赖溢出回绕的逻辑（游戏里"分数到顶变负"之类）都是埋雷。

判断"int 溢出后会绕回到最小值，所以可以用它实现循环计数。"

定宽整数：需要精确宽度时

int 的尺寸随平台漂移，需要保证宽度的场景（文件格式、网络协议、跨平台数据）用定宽整数——它们在 <cstdint> 头文件里：

类型含义常用场景
std::int32_t恰好 32 位有符号跨平台固定宽度
std::int64_t恰好 64 位有符号大数、时间戳
std::uint32_t 等无符号版本按位操作、协议字段
std::size_t对象尺寸/下标的类型sizeof 的返回值、容器大小（第 17 章）
#include <cstdint> // 定宽整数都在这里

std::int32_t w { 100 };      // 保证 32 位
std::int64_t big { 900'000'000'000 };
std::size_t  n { sizeof(int) }; // 4

两处细节：① 定宽类型其实是现有整数的别名——如果平台上 int 恰好 32 位，std::int32_t 就是 int 的马甲（所以 sizeof(int32_t) == sizeof(int)）；② 8 位定宽整数常被当作 char 处理（打印它输出的可能是字符不是数字，4.11 课细讲），要谨慎。

✅ 选型速查（原文建议）
  • 日常整数：int（现代平台够用且最快）
  • 可能超 20 亿：直接 std::int64_t / long long
  • 需要固定宽度（协议/文件/跨平台）：定宽整数
  • 表示"数量/尺寸/下标"：尊重接口给什么用什么（如 size_t），别乱转
  • 永远别为了"省内存"用 short/8 位类型——现代机器上省不出价值，还惹 char 的麻烦
💭 思维转变：数字类型的边界是真实的物理墙

数学里的整数无限延伸；计算机里的整数是固定宽度的比特容器，墙就在那。写 int 时想一句"这个量最大会到多少"——秒级时间戳 47 年（int 秒数在 2038 年溢出，著名的 2038 问题）、人口、字节数……范围思维从此成为你选类型的本能。而"溢出=UB"则再次呼应本章主旋律：C++ 把"检测边界"的责任交给你，把"越界的后果"也交给你。
