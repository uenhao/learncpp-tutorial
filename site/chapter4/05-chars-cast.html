4.5 字符与类型转换

char：最小的大惊喜

📐 概念

char：设计用于存放单个字符，通常 1 字节。字面量用单引号：'a'、'@'、'5'。第 1.9 课你见过它，现在揭底牌：char 本质是个小整数，字符 'A' 存的是整数 65——它是 ASCII 编码表的查询结果。

char c1 { 'A' };  // 存的是 65
char c2 { '5' };  // 注意：这是字符 5，存的是 53 —— 不是数字 5！
char c3 { 65 };   // 合法，等价于 'A'（但别这么写，用字面量更清晰）

ASCII 表值得记住的锚点：'0' 是 48，'A' 是 65，'a' 是 97。由规律可推算：'7' = '0' + 7 = 55；'B' = 66；数字字符之间的差就是数值差（'7' - '0' == 7）。

打印 char：按字符解释，还是按整数解释？

#include <iostream>

int main()
{
    char c { 'A' };
    std::cout << c << '\n';          // A —— cout 默认按"字符"打印

    int i { c };                     // 把 char 提升为 int
    std::cout << i << '\n';          // 65 —— 按"整数"打印

    std::cout << static_cast<int>(c) << '\n'; // 65 —— 显式转换（下文）
    return 0;
}
⚠️ 反例：char 参与算术后打印成整数
char c { 'A' };
std::cout << c + 1 << '\n';   // 打印 66，不是 'B'！

c + 1 把 char 提升为 int 再运算，结果是 int，cout 按 int 打印。想打印 'B' 得先存回 char：char b = c + 1;。理解"char 是整数，只是打印方式不同"，这类现象都能解释。

输入 char 与第 3 章测验的"char 藏 bug"回收

第 3 章综合测验 Q4 里那个程序：用 char x 读数字 8，结果 x 是 56——现在你能解释了：cin >> x 读入的是字符 '8'，存成整数 56（ASCII），后续按 int 参与运算当然全错。读什么类型的数据，就声明什么类型的变量。

类型转换与 static_cast

📐 概念：隐式转换（implicit conversion）

类型不匹配时编译器自动转换——比如把 int 传给需要 double 的参数，5 变成 5.0。方便，但看不见摸不着。

static_cast<目标类型>(值)：显式告诉编译器"我要转换"。它是转换意图的说明书，让代码读者一眼看到"这里有转换发生"。

void print(double x)
{
    std::cout << x << '\n';
}

int main()
{
    print(5);                          // 隐式转换：5 → 5.0，打印 5
    int y { 5 };
    print(y);                          // 同上
    print(static_cast<double>(y));     // 显式：意图清晰
    return 0;
}

回收 1.6 课的欠条：整数除法

1.6 课埋的"7/2 == 3"之迷，现在有标准解法——除法前把操作数转成浮点：

int a { 7 };
int b { 2 };

std::cout << a / b << '\n';                     // 3 —— int/int 整数除法
std::cout << static_cast<double>(a) / b << '\n'; // 3.5 —— 先转再除
std::cout << a / static_cast<double>(b) << '\n'; // 3.5 —— 转一边也行

规则：除法运算中只要有一个操作数是浮点，整个除法就是浮点除法。static_cast 只需转其中一个。

✅ 何时该写 static_cast
  • 安全方向（宽→窄的反向：int→double）编译器自动做且无信息损失，写不写随项目风格；
  • 危险方向（窄化：double→int、大范围→小范围）隐式转换被 1.4 课的 {} 初始化拦住；如果确实要转（你确认丢弃小数是故意的），用 static_cast<int>(3.9) 表明"我明知故转"；
  • 原则：每个 static_cast 都是签名——"这里我知道类型变了，且我审过它的安全性"。

💭 思维转变：一切类型转换都有"方向"和"代价"

本课把第 1 章的三张欠条全部兑付：整数除法（1.6）、char 打印整数（1.9 'A' 与 "A" 之辨的深化）、cin 提取失败的根源（1.4/第 3 章 Q4）。现在你有一张转换地图：char→int→double（宽化，安全，可能隐式发生）；double→int（窄化，丢小数，必须显式表明故意）。类型系统的世界观由此完整：类型 = 宽度 + 解释（4.1）；转换 = 改解释，可能有损。第 10 章还会回到转换与推导，届时地基已打好。
