5.1 常量变量：不许变的名字

程序里有一类特殊的量：初始化之后永远不该再变——重力加速度、圆周率、最大关卡数。用普通变量装它们，谁都能顺手改掉；用字面量写死，又失去名字和语义。这一课给出正解：常量变量。

📐 概念：常量（constant）的两种形态

常量：程序运行期间不可更改的值。C++ 支持两种：

  • 具名常量（named/symbolic constant）：有名字的常量——本课主角；
  • 字面量常量（literal constant）：直接写在代码里的值（5、3.4）——5.2 课展开。

const 变量：定义后禁止赋值

📐 概念：const 变量

声明时加 const 关键字：必须初始化（不给初始值编译错误——常量必须"出生即有值"），此后任何赋值都是编译错误。

const double gravity { 9.8 };  // 常量变量：初始化后不可改
int main()
{
    gravity = 9.81;  // ❌ 编译错误：不能给 const 变量赋值
}

const 变量的初始化：可以来自运行时

📐 const ≠ 编译期已知

const 只承诺"创建后不可改"，不承诺初始值在编译期已知：

int a{};
std::cin >> a;                 // 运行时才确定
const int b{ a };              // ✅ 合法！b 不可改，但值来自运行时
const int c{ 5 + 3 };          // ✅ 初始值编译期已知（8）

这两种 const 有本质区别——"运行时才确定的常量"和"编译期就确定的常量"。5.6 课的 constexpr 正是为后者而生。

命名约定：不需要特殊待遇

流传着两派命名法：C 程序员爱用全大写加下划线（EARTH_GRAVITY），C++ 圈常见 k 前缀（kEarthGravity）。但原文的观点很干脆：const 变量行为上就是普通变量（只是不能赋值），没必要特殊命名——照常使用 camelCase（earthGravity）。全大写常量在 C++ 里反而常被预留给宏（2.6 课的坑）。

两个"不该用 const"的地方

✅ 最佳实践（原文两条明确禁令）
  • 值传递的函数参数不要加 const：void printInt(const int x)——形参本来就是拷贝，函数内部改不改都随它（改了也不影响调用者），加 const 只添乱；
  • 按值返回不要加 const：const int getValue()——对基本类型编译器直接忽略（还可能警告）；返回临时拷贝加 const 毫无意义，还会妨碍移动语义优化。

这两条是"const 用在真正需要的地方"的体现——等到第 12 章引用/指针传递时，const 才真正大显身手。

为什么"能 const 就 const"

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    // ... 使用 x 的过程中，若 x 被意外修改，错误值会静默传播 ...
}

变量能被改，就存在被意外改掉的可能——错误值会顺着后续代码静默传播（3.1 课层级 3）。const 把这类事故在编译期拦下：你想改？编译器拒绝。原文规则：能设为常量的变量，就应该设为常量。这让"哪些量会变"一目了然——读代码时看到没带 const 的变量，就知道它值得多看两眼。

💭 思维转变：const 是"意图的编译器化"

const 的本质是把你的设计意图写进代码交给编译器执法："这个量不许变"。它的收益全部来自"意图被机器验证"：意外赋值从运行时 bug 变成编译错误（3.1 层级 3 → 层级 1，错误提前两站被抓）。这和第 0 章的构建配置、第 2 章的头文件一脉相承——能用编译器锁住的东西，就不要靠自觉。顺便：你此前学的"宏常量别用、用 constexpr"将在 5.6 课正式兑现，本章会先埋好伏笔。
