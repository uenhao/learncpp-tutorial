5.4 std::string 与 string_view

你从 1.4 课就开始用 std::string 存名字——当时"先记住用法"。现在类型观完整了，正式介绍它，并认识它的搭档 string_view。

📐 概念：std::string（<string>）

std::string 不是基本类型——它是"类类型"（第 14 章展开）。要点：它会按需自动分配内存（动态内存分配），所以能装任意长度的文本——这正是它灵活的来源，也是它"与 constexpr 不兼容"（5.3 课）的原因。

#include <string>   // std::string 在这里

int main()
{
    std::string name{ "Alex" };
    name = "Jason";              // 变长！没问题
    name = "Jay";                // 变短！也没问题
    std::string id{ "45" };      // "45" 是文本不是数字——不能当 45 乘除
}

输入字符串的两种方式（重要陷阱）

⚠️ cin >> 遇到空格就停
std::string name{};
std::cin >> name;    // 输入 "John Doe" → 只读到 "John"，" Doe" 留在流里！

下一句 cin >> color 会把残留的 "Doe" 当成 color 的输入——程序"跳过"了第二个提问。1.4 课"cin 提取遇空白分隔"的规则在这里升级成大坑。

📐 解法：std::getline 读整行
std::string name{};
std::getline(std::cin >> std::ws, name);  // 读一整行（含空格）

std::getline：把一整行（到换行为止，不含换行符）读进字符串。std::ws 负责先吞掉行首残留的空白——这让你能混用 cin >>（读数字）和 getline（读文本）而不出乱子。

string_view：只读的"视图"（C++17）

📐 概念：std::string_view（<string_view>）

std::string_view：对已有字符串（C 字符串、std::string、另一个 view）的只读访问，不拷贝数据。它不是新的字符串，是"看已有字符串的一副眼镜"。

背景：拷贝 std::string 开销不小（要分配内存+复制内容）。如果只需要"读"，为什么要付拷贝的代价？

#include <iostream>
#include <string>
#include <string_view>

void printSV(std::string_view str) // 参数用 string_view：零拷贝
{
    std::cout << str << '\n';
}

int main()
{
    std::string_view s{ "Hello, world!" }; // 看着字面量，不拷贝
    printSV(s);

    std::string name{ "Alex" };
    printSV(name);     // ✅ string/string_view/C字符串 都能传入
    printSV("direct"); // ✅
    return 0;
}
✅ 原文最佳实践

需要只读字符串时（尤其函数参数），优先 std::string_view 而非 std::string。它兼容三种字符串来源，省去所有拷贝。

string_view 的代价：视图不是主人

⚠️ 被看的字符串必须活得比 view 久
std::string_view bad{};
{
    std::string s{ "temp" };
    bad = s;   // bad 只是"看着" s，不拷贝
}              // s 在这里销毁！
std::cout << bad << '\n'; // ❌ 视图指向已销毁的内存——未定义行为

"视图"不拥有数据。用眼镜看书，书被扔了，眼镜还架在原处——看的是空气。这条规则 2.2 课"形参是拷贝、返回即销毁"的机制可以完美解释：view 存的是"地址+长度"，地址所指的栈层弹掉，内容即蒸发。现在只需记住结论：别让 string_view 活得比它看的东西久；第 12 章指针会把它机制化。

选型速查

场景用哪个
需要保存/修改字符串std::string（它拥有数据）
只读：传参、临时看看std::string_view（零拷贝）
编译期已知的只读常量字符串constexpr std::string_view（5.3 课：string 与 constexpr 不兼容，view 可以！）

选择写一个"打印传入的名字"的函数，最优参数类型是？

预测用户输入 "John Doe" 后，程序输出什么？

std::string name{};
std::cin >> name;
std::string color{};
std::cin >> color;
std::cout << name << " / " << color;
💭 思维转变：从"值"到"所有权"的第一步

string 与 string_view 的对比，本质是拥有数据 vs 引用数据的对比——这是 C++ 后半程（引用、指针、智能指针）的核心主题的第一次露脸。你可以先用 2.2 课的语言理解它：string 像按值传参（拿拷贝、自己管），view 像"只读地借用"。今天记住选型表（存数据用 string，读数据用 view），等第 12 章你回头再看，会发现自己早已在用所有权思维做决策了。另外注意 getline 的 std::ws 小技巧——混用输入方式时的标准姿势，会伴随你所有交互程序。
