6.2 取余与自增自减

取余（%）：负数签名是重点

📐 概念：x % y 的符号跟谁？

% 取除法的余数（1.6 课已入门）。关键规则：余数的符号与第一个操作数 x 相同。

6 % 4   →  2
-6 % 4  →  -2   （跟 x 的负号）
6 % -4  →  2    （x 是正的）
-6 % -4 →  -2
⚠️ 它叫"余数"（remainder），不叫"模"（modulo）

数学里的"模运算"在负数时结果非负：数学上 −21 mod 4 = 3；而 C++ 的 -21 % 4 = -1。原文据此主张：把 % 叫"余数"更准确——背错名字就会写错负数逻辑。

实战陷阱：负数的奇偶判断

bool isOdd(int x)
{
    return (x % 2) == 1; // ❌ x = -5 时：-5 % 2 = -1，-1 != 1 → 判成偶数！
}
✅ 最佳实践：与 0 比较
return (x % 2) != 0; // ✅ 负数也对：-5 % 2 = -1 ≠ 0 → 奇数

取余结果和 0 比较没有正负号问题。判断偶数同理：写 (x % 2) == 0。

指数运算：C++ 没有 ^，用 pow()

#include <cmath>   // std::pow 在这里

double x{ std::pow(2.0, 10.0) }; // 2 的 10 次方 = 1024

数学里的 ^ 在 C++ 中是按位异或（第 O 章）——又一个"长得像但不是"的陷阱。另外 pow 返回浮点，整数次幂常用循环相乘代替（后续章节）。

++ 与 --：自增自减

📐 概念：前缀与后缀
++x;  // 前缀：x 先加 1，"整个表达式"的值是加 1 后的 x
x++;  // 后缀：x 加 1，但"整个表达式"的值是加 1 前的旧值
--x;  x--; // 减 1 同理

单独一行使用时两者效果相同；嵌进更大的表达式里才见分晓：

int x{ 5 };
std::cout << ++x << '\n'; // x 变 6，打印 6
std::cout << x++ << '\n'; // 打印 6（旧值），x 变 7

副作用与求值顺序：本章最重要的警告

📐 概念：副作用（side effect）——1.6 课词汇的正式定义

副作用：表达式除"产生返回值"之外的可见效果。改变对象值、输入输出、改 GUI 状态都算。赋值 x = 5 的返回值没人用，但副作用（x 永久变 5）才是它的价值。算术运算符只产生值，无副作用。

⚠️ 反例：副作用 + 未定义的求值顺序 = UB
int x { 5 };
int value{ add(x, ++x) }; // 未定义行为！
// 左先求值：add(5, 6) = 11
// 右先求值：add(6, 6) = 12
// 标准不规定函数实参的求值顺序 → 结果不确定 → UB

标准故意不规定实参求值顺序（给编译器优化自由）。只要一条语句里对同一个对象"既用又改"，就掉进这个坑。2.1 课的执行模型（逐语句、顺序执行）在"一条语句内部"有例外——这就是例外现场。

✅ 原文最佳实践（本章头号规则）
  • 一条语句里，对同一变量的副作用不要超过一个；
  • 含 ++/-- 的表达式不要嵌进其他语句——单独一行写 ++x;；
  • 优先用前缀形式（++x）：语义更直白，无"旧值缓存"的心智负担。

预测输出什么？

int x{ 5 };
std::cout << x++ << ' ' << x;  // 同一语句：读 x 又改 x

选择判断奇偶性，负数安全且最符合最佳实践的写法是？

💭 思维转变：语句是安全单元，表达式是危险区

本章给出的心智模型：把程序按语句切分，每条语句内部是"各步骤的求值顺序不完全定义"的危险区。规则简单到极致——一行一件事：++x; 自己一行，函数实参里别放副作用，两个副作用别碰同一个变量。遵守它，你永远不会遇到"add(x, ++x) 是 11 还是 12"的灵异问题。这也是为什么前几章反复强调"每条语句一行"（1.8 格式课）——格式习惯里藏着正确性。
