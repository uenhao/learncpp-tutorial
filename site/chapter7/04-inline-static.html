7.4 inline 与静态局部变量

inline：现代含义早已不是"内联展开"

📐 概念：inline 的历史包袱与现代含义

历史上：inline 是"请把这个函数原地展开"的性能提示。现代 C++：编译器比人更懂该不该展开（且按调用点逐个决定），这条用途已被废弃——

现代含义：允许在多个翻译单元里重复定义而不违反 ODR（链接器把多份定义合并视为一份）。inline 是给 ODR 开的"白名单"。

✅ 最佳实践
  • 别用 inline 请求内联展开——那是 premature optimization（0.2 课 Debug/Release 已让编译器做这件事）；
  • inline 的正确用途：头文件里的函数定义（免 ODR 冲突）与跨文件共享的全局变量（下一节）。

inline 变量：跨文件共享全局常量的现代解法

5.3 课埋的伏笔在此兑现。问题：每个 .cpp 都需要同一批全局常量（如最大玩家数），怎么共享？

方案结果
头文件里定义非 const 全局每个 .cpp 一份定义 → multiple definition（ODR 炸）
头文件里定义 const/constexpr 全局const 默认 internal 链接：各 .cpp 独立副本——能跑，但每个单元都存一份
头文件里定义 inline constexpr✅ 多个定义合法合并 + 保持 constexpr 属性——现代答案
// constants.h
#ifndef CONSTANTS_H
#define CONSTANTS_H

namespace config
{
    inline constexpr int maxPlayers{ 8 };
    inline constexpr double gravity{ 9.8 };
}

#endif

任何 .cpp #include "constants.h" 后直接用 config::maxPlayers——一处定义，处处共享，无 extern、无额外 .cpp。这是 2.12 课头文件保护 + 2.9 课命名空间 + 本课 inline 的三合一实战。

静态局部变量：2.5 课 counter 之谜的答案

📐 概念：static 局部变量

给局部变量加 static：生命周期从"自动"改为"静态"——程序启动时创建、程序结束才销毁（与全局变量同寿命）。效果：出了作用域不销毁、值保留。作用域仍是块内（名字只在那里可见）。

#include <iostream>

void incrementAndPrint()
{
    int value{ 1 };        // 自动：每次调用重建
    ++value;
    std::cout << value << '\n';
} // value 销毁

void incrementAndPrintStatic()
{
    static int s_value{ 1 }; // 静态：只在第一次调用时初始化！
    ++s_value;
    std::cout << s_value << '\n';
} // s_value 不销毁，只是"看不见"

int main()
{
    incrementAndPrint();          // 2
    incrementAndPrint();          // 2
    incrementAndPrint();          // 2 —— 每次都是新的

    incrementAndPrintStatic();    // 2
    incrementAndPrintStatic();    // 3 —— 记住了上一次！
    incrementAndPrintStatic();    // 4
    return 0;
}

注意细节：初始化只在第一次执行——后续调用直接跳过初始化行（这正是"有记忆"的原因）。惯例前缀 s_ 标识静态局部变量。

经典应用：唯一 ID 生成器（原文）

int generateID()
{
    static int s_itemID{ 0 };
    return s_itemID++; // 返回旧值，自身 +1（下次调用得 1、2、3……）
}
⚠️ 静态局部变量的纪律

它和全局变量一样"活到程序结束"，所以 7.3 的警告部分适用：尽量只初始化、少依赖其历史值。原文最佳实践：总是初始化静态局部变量（不初始化则零初始化，但显式写出意图更清晰）。它的优势相比全局：作用域限制在函数内——别的函数碰不到它，危险半径小得多。

预测输出什么（三行）？

void counter()
{
    static int s_calls{ 0 };
    ++s_calls;
    std::cout << s_calls << '\n';
}
int main() { counter(); counter(); counter(); }

判断"static 局部变量出了作用域就销毁，只是值被偷偷保存了。"

💭 思维转变：关键词 static 的三副面孔

static 在本章出现了三次，含义各不相同——靠"作用对象"区分：① static 局部变量 → 改生命周期（自动→静态）；② static 全局变量 → 改链接性（外→内）；③ static 成员（第 15 章）→ 属于类而非对象。一个关键词多种含义是 C++ 的常态，辨析方法是看它修饰什么。另外注意本章的隐喻闭环：2.5 课你说"希望函数有记忆"→ static 局部变量；1.7 课你说"希望有循环处理 100 人"→ 第 8 章循环马上到。
