8.1 分支进阶：if 块、悬挂 else 与 switch

4.4 课的 if 语句在真实代码里还有三件事要讲清楚：块的必要性（悬挂 else）、多分支的专用工具 switch、以及让分支更安全的写法。

悬挂 else：为什么"总是写花括号"再次救你

⚠️ 原文案例：缩进骗人
if (x >= 140)
    std::cout << "You are tall enough to ride.\n";
else
    std::cout << "You are not tall enough to ride.\n";
    std::cout << "Too bad!\n";   // 缩进在 else 里，实际不在！

输入 180 的人也会看到 "Too bad!"——else 只管辖紧跟的那一条语句，第二句是无条件的。缩进是给人看的，编译器只认花括号。这正是 4.4 课"总是写花括号"最佳实践的实锤案例。

📐 概念：悬挂 else（dangling else）

if 嵌套时不加花括号，else 会匹配最近的未匹配 if——你心里的配对可能不是编译器的配对：

if (a)
    if (b)
        std::cout << "a and b\n";
else
    std::cout << "???";  // 这个 else 属于 if(b)，不是 if(a)！

一律写花括号，此类歧义根绝。

switch：多分支的专用工具

📐 概念：switch 语句

把一个整型（或枚举）表达式的值与一组 case 标签比对，命中即从那里开始执行：

  • 命中某 case → 执行其后语句；
  • 无命中但有 default → 执行 default 后语句；
  • 无命中无 default → 整个 switch 跳过。

限制：条件只能是整型/枚举——float、std::string 不行（switch 为高效跳转设计，浮点/字符串无法走那条路）。

#include <iostream>

void printDigitName(int x)
{
    switch (x)
    {
    case 1:
        std::cout << "One";
        return;
    case 2:
        std::cout << "Two";
        return;
    default:
        std::cout << "Unknown";
        return;
    }
}

fallthrough：不加 break 会"跌落"

⚠️ 反例：忘记 break
switch (x)
{
case 1:
    std::cout << "One";
    // 没有 break/return —— 跌落！
case 2:
    std::cout << "Two";
    return;
}

x == 1 时输出 OneTwo——命中 case 1 后继续往下执行所有 case（fallthrough），直到遇到跳转。这是 C++ 最著名的坑之一（C 语言的遗产）。

✅ 最佳实践
  • 每个 case 以 break（跳出 switch）或 return 结尾；
  • 故意跌落时写显式标记 [[fallthrough]];，告诉读者和编译器"这是故意的"；
  • 永远写 default（哪怕只放 assert）——枚举新增值时不会静默漏掉。

预测x = 2 时输出什么？

switch (x)
{
case 1:
    std::cout << "One ";
case 2:
    std::cout << "Two ";
case 3:
    std::cout << "Three ";
    break;
default:
    std::cout << "? ";
}

判断"switch (name)（name 是 std::string）可以像整数那样按值分发。"

💭 思维转变：工具的"适用域"和它的机制绑在一起

switch 为什么只收整型？因为它的实现是跳转表——用值直接算出跳转地址，所以必须离散可枚举。这个限制不是随意的，是机制的自然结果。学 C++ 时多问一句"它为什么这样设计"，限制就不再是死记的条款，而是可推导的结论。
